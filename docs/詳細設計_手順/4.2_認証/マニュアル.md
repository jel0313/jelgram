## 【製造】

### STEP 0:準備

```
cd ~/dev/jelgram/apps/api
uv run pytest
```

✅ 確認:4.1 のテストが `7 passed` になる(始める前に、今の状態が正常なことを確かめておく)

### STEP 1:パッケージを追加する

📘 設計:詳細設計書 5章

```
uv add "pyjwt[crypto]"
```

- `"..."` で囲むのは、zsh が `[ ]` を特別な記号として扱うため

✅ 確認:`pyproject.toml` の `dependencies` に `pyjwt[crypto]` が追加されている

### STEP 2:テストユーザーを作り、トークンを取得する

📘 設計:詳細設計書 9章

ログイン画面はまだないので、Email とパスワードでログインできるテスト用ユーザーを作る。開発用の Supabase プロジェクトでは Email ログインが有効になっている(2026-09-28 に確認済み)。

**2-1. テストユーザーを作る**

1. [Supabase の管理画面](https://supabase.com/dashboard) で **開発用** プロジェクトを開く
2. **Authentication** → **Users** → **Add user** → **Create new user**
3. 次のように入力して **Create user**
   - Email:`test@example.com`(実在しないアドレスでよい)
   - Password:このテスト専用の適当なパスワード(他で使っているものは使わない)
   - **Auto Confirm User?** に ✅(付けないと確認メールが必要になり、ログインできない)

✅ 確認:ユーザー一覧に `test@example.com` が出る。行をクリックして表示される **User UID** をメモしておく(打鍵の K-03 で使う)

**2-2. トークンを取得する**

`<...>` の部分を自分の値に置き換えて実行する。Publishable key は `apps/web/.env.example` の説明どおり、Project Settings → API Keys で確認できる。

```
export TOKEN=$(curl -s -X POST "https://<プロジェクトID>.supabase.co/auth/v1/token?grant_type=password" \
  -H "apikey: <Publishable key>" \
  -H "Content-Type: application/json" \
  -d '{"email": "test@example.com", "password": "<2-1 で決めたパスワード>"}' \
  | python3 -c "import json, sys; print(json.load(sys.stdin)['access_token'])")
```

- Supabase に Email とパスワードでログインし、応答の中の `access_token`(= JWT)だけを取り出して、変数 `TOKEN` に入れている
- `TOKEN` はこのターミナルの中だけで使える。別のターミナルでは、もう一度実行する
- トークンの有効期限は **1時間**。切れたら同じコマンドをもう一度実行する

✅ 確認:`echo $TOKEN` で `eyJ` から始まる長い文字列が表示される

> ⚠️ トークンは1時間だけ使える「あなたの通行証」。チャットや docs/ のファイルには貼らない。

### STEP 3:トークンの中身を見てみる

📘 設計:詳細設計書 3章

コードを書く前に、これから検証するものの中身を自分の目で見ておく。

```
uv run python -c "import jwt, os; print(jwt.get_unverified_header(os.environ['TOKEN']))"
uv run python -c "import jwt, os, pprint; pprint.pprint(jwt.decode(os.environ['TOKEN'], options={'verify_signature': False}))"
```

- 1行目:ヘッダー(①)を表示する
- 2行目:**署名を確かめずに** ペイロード(②)を表示する。中身を見るためだけの書き方で、アプリのコードでは絶対に使わない

✅ 確認

- ヘッダーの `alg` が `ES256`、`kid` が入っている
- ペイロードに `sub`(= 2-1 でメモした User UID)、`email`、`aud: 'authenticated'`、`iss`、`exp` がある
- `iss` が `https://<プロジェクトID>.supabase.co/auth/v1` で、`.env` の `SUPABASE_URL` + `/auth/v1` と一致している

> 💡 jwt.io などの Web サイトでも中身を見られるが、本物のトークンを外部のサイトに貼るのは避ける。

### STEP 4:`app/auth.py` を作る

📘 設計:詳細設計書 6.1

作業の順番

1. 必要なものを読み込む(`functools` の `lru_cache`、`typing` の `Annotated`、`uuid` の `UUID`、`jwt`、`fastapi` の `Depends`・`HTTPException`、`fastapi.security` の `HTTPBearer`・`HTTPAuthorizationCredentials`、`pydantic` の `BaseModel`・`ValidationError`、`app.config` の `Settings`・`get_settings`)
2. 定数 `JWT_ALGORITHMS`・`JWT_AUDIENCE` と、`bearer_scheme` を書く
3. `CurrentUser` モデルを作る
4. `get_jwks_client()` を書き、キャッシュを付ける
5. `get_current_user()` を、詳細設計書の「処理の流れ」① → ⑤ の順に書く(`async` を付けない)
6. ファイルの最後に `CurrentUserDep` を書く

✅ 確認:次のコマンドで、Supabase から公開鍵を取得できるかを確かめる

```
uv run python -c "import os; from app.auth import get_jwks_client; print(get_jwks_client().get_signing_key_from_jwt(os.environ['TOKEN']).key_id)"
```

STEP 3 で見た `kid` と同じ文字列が表示されれば OK。

### STEP 5:`app/routers/me.py` を作り、`main.py` に登録する

📘 設計:詳細設計書 6.2・6.3

作業の順番

1. `me.py` で必要なものを読み込む(`APIRouter`、`app.auth` の `CurrentUser`・`CurrentUserDep`)
2. `router` を作る(タグは `auth`)
3. `GET /me` の関数を書き、受け取った `user` をそのまま返す
4. `main.py` の import に `me` を足し、`app.include_router(me.router)` を追加する

### STEP 6:起動して確認する

ターミナルを2つ使う。

**ターミナル A(サーバー)**

```
uv run fastapi dev app/main.py
```

**ターミナル B(確認用。STEP 2 で `TOKEN` を入れたターミナル)**

```
curl -i http://localhost:8000/me
curl -i -H "Authorization: Bearer $TOKEN" http://localhost:8000/me
```

- `-i`:応答のヘッダーも表示する(ステータスコードと `www-authenticate` を見るため)

✅ 確認

- 1つ目:`HTTP/1.1 401`、`www-authenticate: Bearer`、`{"detail":"認証が必要です"}`
- 2つ目:`HTTP/1.1 200`、`{"id":"<User UID>","email":"test@example.com"}`

確認できたらターミナル A を `Ctrl + C` で止める。

> ここまでで【製造】は完了。WBS の 4.2「製造」を ✅ にする。

## 困ったときは

| 症状                                                                          | 原因と対処                                                                                                                                         |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ModuleNotFoundError: No module named 'jwt'`                                  | STEP 1 をしていない。`uv add "pyjwt[crypto]"` を実行する(`uv add jwt` は別のパッケージなので使わない)                                            |
| `Algorithm 'ES256' could not be found`・`Unable to find an algorithm for key` などが出る | `[crypto]` を付けずに入れている。`uv add "pyjwt[crypto]"` を実行し直す                                                                             |
| STEP 2-2 で `KeyError: 'access_token'`                                        | ログインに失敗している。`\| python3 ...` より前だけを実行してエラー内容を見る。`invalid_credentials` ならパスワード違い、`email_not_confirmed` なら 2-1 の Auto Confirm を忘れている |
| STEP 2-2 で `Invalid API key`                                                 | `apikey` に Secret key を入れている、または値が違う。**Publishable key**(`sb_publishable_...`)を使う                                              |
| 本物のトークンなのに `401 トークンが無効です`                                 | ① 期限切れ(1時間)→ STEP 2-2 をやり直す ② `.env` の `SUPABASE_URL` の末尾に `/` がある ③ `issuer` の組み立てが STEP 3 で見た `iss` と違う |
| `503 認証サーバーに接続できません`                                            | Supabase につながらない。開発用プロジェクトが一時停止されていないか管理画面で確認し、停止中なら再開する。`SUPABASE_URL` のタイプミスも確認        |
| `PyJWKClientError: Unable to find a signing key that matches`                 | 別の Supabase プロジェクト(本番用など)で発行したトークンを使っている。開発用プロジェクトでトークンを取り直す                                     |
| `/me` が 503 ではなく 401 になる(つながらないとき)                         | `except` の順番が逆。`PyJWKClientConnectionError` を `PyJWKClientError` より先に書く(詳細設計書 6.1 の実装のヒント)                              |
| テストが本物の Supabase にアクセスしようとして遅い・失敗する                  | 差し替えが効いていない。`dependency_overrides` のキーが `app.auth` の `get_jwks_client` そのものになっているか、リクエストより前に設定しているか確認 |
| `test_auth.py` だけなら通るのに、全部まとめて実行すると失敗する               | 差し替えを戻していない。fixture の `yield` の後で `app.dependency_overrides.clear()` する                                                          |
| T-10(`exp` なし)が `200` になる                                             | `jwt.decode` の `options={"require": [...]}` がない、または `exp` が入っていない                                                                   |
| T-11(UUID でない)で `500 Internal Server Error`                            | `CurrentUser(...)` を作るところで出る `pydantic.ValidationError` を受け取っていない                                                                |
| `/docs` の Authorize でトークンを入れても 401                                 | `Bearer ` を付けて貼っている。トークンだけを貼る                                                                                                   |
| `/docs` に Authorize ボタンが出ない                                           | `get_current_user` の引数で `Depends(bearer_scheme)` を使っていない。`HTTPBearer` を依存として使うと、自動でボタンが表示される                     |
