### STEP 2:テストユーザーを作り、トークンを取得する

📘 設計:詳細設計書 9章

ログイン画面はまだないので、Email とパスワードでログインできるテスト用ユーザーを作る。開発用の Supabase プロジェクトでは Email ログインが有効になっている(2026-09-28 に確認済み)。

**2-1. テストユーザーを作る**

1. [Supabase の管理画面](https://supabase.com/dashboard) で **開発用** プロジェクトを開く
2. **Authentication** → **Users** → **Add user** → **Create new user**
3. 次のように入力して **Create user**
   - Email:`test@example.com`(実在しないアドレスでよい)
   - Password:このテスト専用の適当なパスワード(他で使っているものは使わない)
   - **Auto Confirm User?** に ✅(付けないと確認メールが必要になり、ログインできない)

✅ 確認:ユーザー一覧に登録したメールアドレスが出る。行をクリックして表示される **User UID** をメモしておく(打鍵の K-03 で使う)

**2-2. トークンを取得する**

まず、パスワードを変数 `PW` に入れる。コマンドに直接書くと履歴に残るため、画面に表示されない形で入力する。

```
read -s "PW?パスワード: "
```

- コマンドは **そのまま** 実行する。`?` の後ろは画面に出す案内文なので、ここにパスワードを書かない
- `パスワード: ` と表示されて止まったら、2-1 で決めたパスワードを打って Enter。入力した文字は表示されないが正常
- `echo ${#PW}` でパスワードの文字数が表示されれば入っている(`0` なら空)

次に、`<...>` の部分を自分の値に置き換えて実行する。Publishable key は Project Settings → API Keys で確認できる(ブラウザに公開される前提のキーなので、画面やメモに書いても問題ない)。

```
export TOKEN=$(curl -s -X POST "https://<プロジェクトID>.supabase.co/auth/v1/token?grant_type=password" \
  -H "apikey: <Publishable key>" \
  -H "Content-Type: application/json" \
  -d "{\"email\": \"<2-1 で登録したメールアドレス>\", \"password\": \"$PW\"}" \
  | python3 -c "import json, sys; print(json.load(sys.stdin)['access_token'])")
```

- メールアドレスは、2-1 で **実際に登録したもの** にする(例の `test@example.com` のままだと、ユーザーが見つからずに失敗する)
- Supabase に Email とパスワードでログインし、応答の中の `access_token`(= JWT)だけを取り出して、変数 `TOKEN` に入れている
- `TOKEN` はこのターミナルの中だけで使える。別のターミナルでは、もう一度実行する
- トークンの有効期限は **1時間**。切れたら同じコマンドをもう一度実行する

✅ 確認:`echo $TOKEN` で `eyJ` から始まる長い文字列が表示される

> ⚠️ トークンは1時間だけ使える「あなたの通行証」。チャットや docs/ のファイルには貼らない。

📚 公式:[Supabase のパスワードログイン](https://supabase.com/docs/guides/auth/passwords#signing-in-with-an-email-and-password)・[curl のオプション](https://curl.se/docs/manpage.html)

### STEP 3:トークンの中身を見てみる

📘 設計:詳細設計書 3章

コードを書く前に、これから検証するものの中身を自分の目で見ておく。

```
uv run python -c "import jwt, os; print(jwt.get_unverified_header(os.environ['TOKEN']))"
uv run python -c "import jwt, os, pprint; pprint.pprint(jwt.decode(os.environ['TOKEN'], options={'verify_signature': False}))"
```

- 1行目:ヘッダー(①)を表示する
- 2行目:**署名を確かめずに** ペイロード(②)を表示する。中身を見るためだけの書き方で、アプリのコードでは絶対に使わない

✅ 確認

- ヘッダーの `alg` が `ES256`、`kid` が入っている
- ペイロードに `sub`(= 2-1 でメモした User UID)、`email`、`aud: 'authenticated'`、`iss`、`exp` がある
- `iss` が `https://<プロジェクトID>.supabase.co/auth/v1` で、`.env` の `SUPABASE_URL` + `/auth/v1` と一致している

> 💡 jwt.io などの Web サイトでも中身を見られるが、本物のトークンを外部のサイトに貼るのは避ける。

📚 公式:[署名を確かめずに中身を見る](https://pyjwt.readthedocs.io/en/stable/usage.html#reading-the-claimset-without-validation)・[Supabase のクレーム一覧](https://supabase.com/docs/guides/auth/jwt-fields)

### STEP 4:`app/auth.py` を作る

📘 設計:詳細設計書 6.1

`app/auth.py` を新規作成し、次の内容を書く。

```python
"""認証(Supabase が発行した JWT の検証)。

各エンドポイントは引数に `user: CurrentUserDep` と書くだけで、認証が必須になる。
"""

from functools import lru_cache
from typing import Annotated
from uuid import UUID

import jwt
from fastapi import Depends, HTTPException
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from pydantic import BaseModel, ValidationError

from app.config import Settings, get_settings

# 許可する署名方式。トークン側の alg は信じない
JWT_ALGORITHMS = ["ES256"]
# ログイン済みユーザー向けのトークンだけを通す
JWT_AUDIENCE = "authenticated"

# Authorization: Bearer <トークン> を取り出す。/docs の Authorize ボタンもこれで表示される
bearer_scheme = HTTPBearer(auto_error=False)


class CurrentUser(BaseModel):
    """ログイン中のユーザー。"""

    id: UUID
    email: str | None = None


def _unauthorized(detail: str) -> HTTPException:
    return HTTPException(status_code=401, detail=detail, headers={"WWW-Authenticate": "Bearer"})


@lru_cache
def get_jwks_client() -> jwt.PyJWKClient:
    """Supabase の公開鍵(JWKS)を取得するクライアントを返す。

    取得した公開鍵はクライアントの中でキャッシュされるため、アプリ全体で1つを使い回す。
    """
    settings = get_settings()
    return jwt.PyJWKClient(f"{settings.supabase_url}/auth/v1/.well-known/jwks.json", timeout=5)


def get_current_user(
    credentials: Annotated[HTTPAuthorizationCredentials | None, Depends(bearer_scheme)],
    jwks_client: Annotated[jwt.PyJWKClient, Depends(get_jwks_client)],
    settings: Annotated[Settings, Depends(get_settings)],
) -> CurrentUser:
    """JWT を検証し、ログイン中のユーザーを返す。

    公開鍵の取得でブロックする通信を行うため、async def にしない。
    """
    if credentials is None:
        raise _unauthorized("認証が必要です")
    token = credentials.credentials

    try:
        signing_key = jwks_client.get_signing_key_from_jwt(token)
    except jwt.PyJWKClientConnectionError as e:
        raise HTTPException(status_code=503, detail="認証サーバーに接続できません") from e
    except (jwt.PyJWKClientError, jwt.InvalidTokenError) as e:
        raise _unauthorized("トークンが無効です") from e

    try:
        claims = jwt.decode(
            token,
            signing_key.key,
            algorithms=JWT_ALGORITHMS,
            audience=JWT_AUDIENCE,
            issuer=f"{settings.supabase_url}/auth/v1",
            options={"require": ["exp", "sub", "aud", "iss"]},
        )
        return CurrentUser(id=claims["sub"], email=claims.get("email"))
    except (jwt.InvalidTokenError, ValidationError) as e:
        raise _unauthorized("トークンが無効です") from e


CurrentUserDep = Annotated[CurrentUser, Depends(get_current_user)]
```

| `import jwt` | PyJWT を読み込む。インストールするときの名前は `pyjwt`、読み込むときの名前は `jwt` |
| `from fastapi import Depends, HTTPException` | `Depends`:依存関数を指定する。`HTTPException`:投げるとエラーの応答(401 など)になる例外 |
| `from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer` | Bearer トークンを取り出す部品(`HTTPBearer`)と、取り出した結果の型 |

| `JWT_ALGORITHMS = ["ES256"]` | 受け付ける署名方式のリスト。これ以外の方式のトークンは拒否する |

| `bearer_scheme = HTTPBearer(auto_error=False)` | ヘッダーからトークンを取り出す部品を作る。`auto_error=False` は「トークンがなくても自動でエラーにせず `None` を返す」(エラーは自分で日本語で出すため) |

| コード | 何をしているか |
| --- | --- |
| `class CurrentUser(BaseModel):` | ログイン中のユーザーを表すモデル |
| `id: UUID` | ユーザー ID。UUID の形でない値で作ろうとすると `ValidationError` になる |
| `email: str \| None = None` | メールアドレス。`str \| None` は「文字列か None」。省略したら None |

| コード | 何をしているか |
| --- | --- |
| `@lru_cache` | 結果を覚えておく印。これでクライアントがアプリ全体で 1 つだけになり、取ってきた公開鍵の保存(キャッシュ)が効く |
| `def get_jwks_client() -> jwt.PyJWKClient:` | 公開鍵を取ってくるクライアントを返す関数 |
| `settings = get_settings()` | 設定を読む |
| `return jwt.PyJWKClient(f"{settings.supabase_url}/auth/v1/.well-known/jwks.json", timeout=5)` | 公開鍵の置き場の URL を渡してクライアントを作る。`f"…{変数}…"` は `{}` の中に変数の値を埋め込む書き方(f 文字列)。`timeout=5` は「5 秒応答がなければ諦める」 |

**改札の本体(`get_current_user`)**

| コード | 何をしているか |
| --- | --- |
| `def get_current_user(` | 依存関数の定義。`async def` ではなく `def` にしている(公開鍵を取る通信は「待つ」タイプなので、FastAPI に別のスレッドで実行してもらう) |
| `credentials: Annotated[HTTPAuthorizationCredentials \| None, Depends(bearer_scheme)],` | 「`bearer_scheme` を実行した結果を `credentials` に入れて」という指定。結果はトークンの情報か None |
| `jwks_client: Annotated[jwt.PyJWKClient, Depends(get_jwks_client)],` | 「`get_jwks_client()` の結果を入れて」。テストではここを偽物に差し替える |
| `settings: Annotated[Settings, Depends(get_settings)],` | 「`get_settings()` の結果を入れて」 |
| `) -> CurrentUser:` | 戻り値は `CurrentUser` |
| `if credentials is None:` | トークンがない(ヘッダーがない・`Bearer` 以外の方式)なら |
| `raise _unauthorized("認証が必要です")` | `raise` で例外を投げる。処理はここで止まり、FastAPI が 401 の応答を返す |

| `audience=JWT_AUDIENCE,` | `aud` が `authenticated` でなければ拒否 |
| `issuer=f"{settings.supabase_url}/auth/v1",` | `iss` が自分の Supabase でなければ拒否 |
| `options={"require": ["exp", "sub", "aud", "iss"]},` | この 4 つのクレームがなければ拒否。期限(`exp`)が過ぎていないかのチェックは自動で行われる |

| `CurrentUserDep = Annotated[CurrentUser, Depends(get_current_user)]` | 「`get_current_user` を通った `CurrentUser`」を 1 語で書ける別名。各 API は `user: CurrentUserDep` と書くだけでよい |

### STEP 5:`app/routers/me.py` を作り、`main.py` に登録する

📘 設計:詳細設計書 6.2・6.3

**① `app/routers/me.py` を新規作成**

```python
"""ログイン中のユーザー情報 API(認証の確認用)。"""

from fastapi import APIRouter

from app.auth import CurrentUser, CurrentUserDep

router = APIRouter(tags=["auth"])


@router.get("/me", response_model=CurrentUser)
def me(user: CurrentUserDep) -> CurrentUser:
    """トークンで特定したユーザーを返す。DB には接続しない。"""
    return user
```

## 困ったときは

| 症状                                                                          | 原因と対処                                                                                                                                         |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ModuleNotFoundError: No module named 'jwt'`                                  | STEP 1 をしていない。`uv add "pyjwt[crypto]"` を実行する(`uv add jwt` は別のパッケージなので使わない)                                            |
| `Algorithm 'ES256' could not be found`・`Unable to find an algorithm for key` などが出る | `[crypto]` を付けずに入れている。`uv add "pyjwt[crypto]"` を実行し直す                                                                             |
| `echo $TOKEN` で何も表示されない                                              | STEP 2-2 の `export TOKEN=$(...)` を実行していない、または別のターミナルで見ている。同じターミナルで 2-2 を実行する |
| STEP 2-2 で `KeyError: 'access_token'`                                        | ログインに失敗している。`\| python3 ...` より前だけを実行してエラー内容を見る。`invalid_credentials` ならメールアドレスかパスワードの違い(`PW` が空の場合も含む)、`email_not_confirmed` なら 2-1 の Auto Confirm を忘れている |
| STEP 2-2 で `Invalid API key`                                                 | `apikey` に Secret key を入れている、または値が違う。**Publishable key**(`sb_publishable_...`)を使う                                              |
| 本物のトークンなのに `401 トークンが無効です`                                 | ① 期限切れ(1時間)→ STEP 2-2 をやり直す ② `.env` の `SUPABASE_URL` の末尾に `/` がある ③ `issuer` の組み立てが STEP 3 で見た `iss` と違う |
| `503 認証サーバーに接続できません`                                            | Supabase につながらない。開発用プロジェクトが一時停止されていないか管理画面で確認し、停止中なら再開する。`SUPABASE_URL` のタイプミスも確認        |
| `PyJWKClientError: Unable to find a signing key that matches`                 | 別の Supabase プロジェクト(本番用など)で発行したトークンを使っている。開発用プロジェクトでトークンを取り直す                                     |
| `/me` が 503 ではなく 401 になる(つながらないとき)                         | `except` の順番が逆。`PyJWKClientConnectionError` を `PyJWKClientError` より先に書く(STEP 4 のコード)                                            |
| テストが本物の Supabase にアクセスしようとして遅い・失敗する                  | 差し替えが効いていない。`dependency_overrides` のキーが `app.auth` の `get_jwks_client` そのものになっているか、リクエストより前に設定しているか確認 |
| `test_auth.py` だけなら通るのに、全部まとめて実行すると失敗する               | 差し替えを戻していない。fixture の `yield` の後で `app.dependency_overrides.clear()` する                                                          |
| T-10(`exp` なし)が `200` になる                                             | `jwt.decode` の `options={"require": [...]}` がない、または `exp` が入っていない                                                                   |
| T-11(UUID でない)で `500 Internal Server Error`                            | `CurrentUser(...)` を作るところで出る `pydantic.ValidationError` を受け取っていない                                                                |
| `/docs` の Authorize でトークンを入れても 401                                 | `Bearer ` を付けて貼っている。トークンだけを貼る                                                                                                   |
| `/docs` に Authorize ボタンが出ない                                           | `get_current_user` の引数で `Depends(bearer_scheme)` を使っていない。`HTTPBearer` を依存として使うと、自動でボタンが表示される                     |
