## 【製造】

### STEP 0:準備

新しいターミナルを開き、`apps/api` に移動する。以降のコマンドはすべて `apps/api` で実行する。

```
cd ~/Desktop/作業用/jelgram/apps/api
```

✅ 確認:`uv --version` でバージョンが表示される

### STEP 1:uv のプロジェクトを作る

```
uv init --bare --name jelgram-api
```

- `--bare`:設定ファイル(`pyproject.toml`)だけを作る。サンプルのファイルは作らない

✅ 確認:`apps/api/pyproject.toml` ができている

### STEP 2:パッケージを追加する

```
uv add "fastapi[standard]" pydantic-settings
uv add --dev pytest ruff
```

- 1行目:アプリ本体で使うパッケージ
- 2行目:開発のときだけ使うパッケージ(`--dev`)
- 初回は Python 本体のダウンロードも行われるので、少し時間がかかる

✅ 確認

- `apps/api/.venv/` と `apps/api/uv.lock` ができている
- `pyproject.toml` の `dependencies` に `fastapi` と `pydantic-settings`、`[dependency-groups]` の `dev` に `pytest` と `ruff` が書かれている

### STEP 3:pytest と Ruff の設定を追記する

`pyproject.toml` の末尾に、次の内容を追記する。

```toml
[tool.pytest.ini_options]
pythonpath = ["."]
testpaths = ["tests"]

[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

| 設定                    | 意味                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| `pythonpath = ["."]`    | テストから `import app...` できるようにする                                               |
| `testpaths = ["tests"]` | `tests/` の中だけをテストとして探す                                                       |
| `line-length = 100`     | 1行の最大文字数                                                                           |
| `select = [...]`        | E/F:基本的な誤り、I:import の並び順、UP:新しい書き方への置き換え、B:バグになりやすい書き方 |

✅ 確認:`uv run pytest` を実行すると「no tests ran」と表示される(テストがまだないので正常)

### STEP 4:フォルダと空のファイルを作る

```
mkdir -p app/routers tests
touch app/__init__.py app/routers/__init__.py
```

✅ 確認:次の形になっている(`.venv` などは省略)

```
apps/api/
├── app/
│   ├── __init__.py
│   └── routers/
│       └── __init__.py
└── tests/
```

### STEP 5:`app/config.py` を作る

📘 設計:詳細設計書 5.1

作業の順番

1. 必要なものを読み込む(`functools`、`pydantic` の `Field`、`pydantic_settings` の `BaseSettings` と `SettingsConfigDict`)
2. `Settings` クラスを作り、`model_config` で `.env` の読み込みと「知らない項目は無視」を指定する
3. フィールド一覧(11項目)を、型・必須・初期値・制約どおりに書く
4. `cors_origins` プロパティを書く
5. クラスの外に `get_settings()` 関数を書き、キャッシュを付ける

✅ 確認:次のコマンドで、`.env` の値が読めているかを確かめる

```
uv run python -c "from app.config import get_settings; print(get_settings().cors_origins)"
```

`['http://localhost:3000']` と表示されれば OK。
エラーになったら、エラーメッセージの最後の数行を読んで、どのフィールドが原因かを確認する。

### STEP 6:`app/routers/health.py` を作る

📘 設計:詳細設計書 5.2

作業の順番

1. 必要なものを読み込む(`typing` の `Literal`、`fastapi` の `APIRouter`、`pydantic` の `BaseModel`)
2. `router` を作る(タグは `health`)
3. `HealthResponse` モデルを作る
4. `GET /health` の関数を書き、`{"status": "ok"}` の内容で `HealthResponse` を返す

✅ 確認:この時点ではまだ起動できない(`main.py` がないため)。次の STEP へ進む

### STEP 7:`app/main.py` を作る

📘 設計:詳細設計書 5.3・5.4

作業の順番

1. 必要なものを読み込む(`FastAPI`、`CORSMiddleware`、`get_settings`、`health`)
2. `settings = get_settings()` で設定を読む
3. `app = FastAPI(...)` でアプリを作る(変数名は必ず `app`)
4. `app.add_middleware(...)` で CORS を追加する(設定値は詳細設計書 5.4 の表どおり)
5. `app.include_router(...)` で health のルーターを登録する

### STEP 8:起動して確認する

```
uv run fastapi dev app/main.py
```

✅ 確認

- ログに `http://127.0.0.1:8000` が表示され、エラーが出ていない
- ブラウザで [http://localhost:8000/health](http://localhost:8000/health) を開くと `{"status":"ok"}` が表示される

確認できたら `Ctrl + C` でサーバーを止める。

> ここまでで【製造】は完了。WBS の 4.1「製造」を ✅ にする。

## 【テスト】

📘 設計:詳細設計書 7章

### STEP 9:テストを書いて実行する

作るファイルと順番

| 順番 | ファイル               | 書く内容                                                        |
| ---- | ---------------------- | --------------------------------------------------------------- |
| 1    | `tests/conftest.py`    | ダミーの環境変数の設定 → `app` の読み込み → fixture `client`    |
| 2    | `tests/test_health.py` | T-01・T-02・T-03                                                |
| 3    | `tests/test_config.py` | T-04・T-05・T-06・T-07                                          |

- テスト関数の名前は `test_` で始める(例:`test_health_returns_ok`)。pytest はこの名前の関数だけをテストとして実行する
- 1つ書くたびに実行すると、どこで失敗したか分かりやすい

実行コマンド

```
uv run pytest -v
```

✅ 確認:7件すべてが `PASSED` になり、最後に `7 passed` と表示される

> 💡 **わざと失敗させてみる**:T-01 の期待値を `"ng"` に書き換えて実行し、`FAILED` になることを確かめる(確認したら元に戻す)。「失敗すべきときにちゃんと失敗する」ことを見ておくと、テストが正しく動いている自信が持てる。

### STEP 10:Ruff でコードを整える

```
uv run ruff format .
uv run ruff check .
```

- 1行目:書き方(空白・改行など)を自動で整える
- 2行目:問題のある書き方を指摘する。`--fix` を付けると、自動で直せるもの(import の並び順など)は直してくれる

✅ 確認

- `ruff check .` が `All checks passed!` と表示される
- もう一度 `uv run pytest` を実行して、7件とも成功する(整形でテストが壊れていないことの確認)

> ここまでで【テスト】は完了。WBS の 4.1「テスト」を ✅ にする。

## 困ったときは

| 症状                                                               | 原因と対処                                                                                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `ModuleNotFoundError: No module named 'app'`                       | `apps/api` 以外の場所で実行している。`pwd` で場所を確認し、`apps/api` に移動する。テストの場合は STEP 3 の `pythonpath` の設定を確認 |
| 起動時に `ValidationError` と `Field required` が出る              | `.env` に必須項目が書かれていない。エラーに出ているフィールド名を `.env` で確認する                          |
| 起動時に `String should have at least 1 character` が出る          | `.env` の必須項目の値が空。値を入れる                                                                        |
| `Address already in use`                                           | 別のターミナルでサーバーが起動したまま。そちらを `Ctrl + C` で止める                                        |
| `fastapi: command not found`                                       | `uv run` を付け忘れている。`uv run fastapi dev app/main.py` のように実行する                                 |
| テストで本物の `.env` の値が使われてしまう                         | conftest.py で、環境変数の設定が `import` より後になっている(詳細設計書 7.1 のつまずきポイント)            |
| Ruff が `E402 Module level import not at top of file` を出す       | conftest.py の意図的な書き方によるもの。その import 行の末尾に `# noqa: E402` を付ける                       |
| T-02 で `400` が返る                                               | `allow_methods` か `allow_origins` の設定が詳細設計書 5.4 と違う                                            |
| VS Code で import に赤い波線が出る                                 | VS Code が `.venv` の Python を使っていない。`Cmd + Shift + P` →「Python: Select Interpreter」→ `apps/api/.venv` を選ぶ |
