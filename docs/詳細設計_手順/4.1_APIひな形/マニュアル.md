### STEP 0:準備

新しいターミナルを開き、`apps/api` に移動する。以降のコマンドはすべて `apps/api` で実行する。

```
cd ~/dev/jelgram/apps/api
```

### STEP 1:uv のプロジェクトを作る

```
uv init --bare --name jelgram-api
```

- `--bare`:設定ファイル(`pyproject.toml`)だけを作る。サンプルのファイルは作らない

### STEP 2:パッケージを追加する

```
uv add "fastapi[standard]" pydantic-settings
uv add --dev pytest ruff httpx2
```

- 1行目:アプリ本体で使うパッケージ
- 2行目:開発のときだけ使うパッケージ(`--dev`)。`httpx2` は TestClient が使う通信ライブラリの新版(入れないとテスト実行時に非推奨の警告が出る)
- 初回は Python 本体のダウンロードも行われるので、少し時間がかかる

✅ 確認

- `apps/api/.venv/` と `apps/api/uv.lock` ができている
- `pyproject.toml` の `dependencies` に `fastapi` と `pydantic-settings`、`[dependency-groups]` の `dev` に `pytest`・`ruff`・`httpx2` が書かれている

📚 公式:[uv add](https://docs.astral.sh/uv/concepts/projects/dependencies/#adding-dependencies)・[--dev](https://docs.astral.sh/uv/concepts/projects/dependencies/#development-dependencies)

### STEP 3:pytest と Ruff の設定を追記する

`pyproject.toml` の末尾に、次の内容を追記する。

```toml
[tool.pytest.ini_options]
pythonpath = ["."]
testpaths = ["tests"]

[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

| 設定                    | 意味                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| `pythonpath = ["."]`    | テストから `import app...` できるようにする                                               |
| `testpaths = ["tests"]` | `tests/` の中だけをテストとして探す                                                       |
| `line-length = 100`     | 1行の最大文字数                                                                           |
| `select = [...]`        | E/F:基本的な誤り、I:import の並び順、UP:新しい書き方への置き換え、B:バグになりやすい書き方 |

✅ 確認:`uv run pytest` を実行すると「no tests ran」と表示される(テストがまだないので正常)

📚 公式:[pytest の pythonpath](https://docs.pytest.org/en/stable/reference/reference.html#confval-pythonpath)・[Ruff の設定](https://docs.astral.sh/ruff/configuration/)・[Ruff のルール一覧](https://docs.astral.sh/ruff/rules/)

### STEP 5:`app/config.py` を作る

📘 設計:詳細設計書 5.1

`app/config.py` を新規作成し、次の内容を書く。

```python
"""アプリの設定(環境変数・.env から読み込む)。"""

from functools import lru_cache

from pydantic import Field
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    """環境変数と .env から読み込む設定値。

    必須項目が未設定・空文字の場合は、生成時(= 起動時)に ValidationError になる。
    """

    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    # Supabase
    supabase_url: str = Field(min_length=1)
    supabase_secret_key: str = Field(min_length=1)
    database_url: str = Field(min_length=1)
    supabase_storage_bucket: str = "post-images"

    # Gemini API
    gemini_api_key: str = Field(min_length=1)
    gemini_model: str = "gemini-3.5-flash-lite"

    # レート制限(要件定義書 4.2)
    rate_limit_per_user_per_minute: int = Field(default=10, ge=1)
    rate_limit_per_user_per_day: int = Field(default=30, ge=1)
    rate_limit_global_per_minute: int = Field(default=12, ge=1)
    rate_limit_global_per_day: int = Field(default=400, ge=1)

    # CORS で許可するオリジン(カンマ区切り)
    cors_allow_origins: str = "http://localhost:3000"

    @property
    def cors_origins(self) -> list[str]:
        """cors_allow_origins をリストに変換する(前後の空白・空の要素は除く)。"""
        return [origin.strip() for origin in self.cors_allow_origins.split(",") if origin.strip()]


@lru_cache
def get_settings() -> Settings:
    """設定を返す。初回に読み込んだものを使い回す。"""
    return Settings()
```

<details>
<summary>🔰 1行ずつの解説(クリックで開く)</summary>

| コード | 何をしているか |
| --- | --- |
| `"""アプリの設定(…)。"""` | ファイルの説明文(docstring)。ファイルの先頭に `"""` で囲んだ文字列を書くと、そのファイルの説明になる。動作には影響しない |
| `from functools import lru_cache` | Python に最初から入っている `functools` から、「関数の結果を覚えておく道具」`lru_cache` を読み込む |
| `from pydantic import Field` | 値に制約(空文字は不可、1 以上 など)を付けるための `Field` を読み込む |
| `from pydantic_settings import BaseSettings, SettingsConfigDict` | 設定クラスの元になる `BaseSettings` と、その読み込み方を指定する `SettingsConfigDict` を読み込む |
| `class Settings(BaseSettings):` | `BaseSettings` を引き継いだ(継承した)クラス `Settings` を作る。引き継ぐだけで「環境変数や `.env` から値を読む」機能が付く |
| `model_config = SettingsConfigDict(env_file=".env", extra="ignore")` | 読み込み方の指定。`env_file=".env"` は「`.env` ファイルも読む」、`extra="ignore"` は「`.env` にクラスにない項目があっても無視する」 |
| `supabase_url: str = Field(min_length=1)` | 項目 `supabase_url` を作る。`str` は文字列型、`min_length=1` は「1 文字以上(空は不可)」。初期値がないので **必須**。環境変数 `SUPABASE_URL` の値が入る(大文字・小文字は区別されない) |
| `supabase_secret_key`・`database_url`・`gemini_api_key` の行 | 上と同じ形。どれも必須で、空文字は不可 |
| `supabase_storage_bucket: str = "post-images"` | `=` の右が初期値。`.env` に書かなければ `"post-images"` になる |
| `gemini_model: str = "gemini-3.5-flash-lite"` | 同じく初期値付き |
| `rate_limit_per_user_per_minute: int = Field(default=10, ge=1)` | `int` は整数型。`default=10` は初期値、`ge=1` は「1 以上」(greater than or equal)。0 以下を入れるとエラー |
| 残りの `rate_limit_...` の 3 行 | 上と同じ形で、初期値だけが違う |
| `cors_allow_origins: str = "http://localhost:3000"` | 許可するオリジンを、カンマ区切りの 1 つの文字列で持つ |
| `@property` | 次のメソッドを「プロパティ」にする印。`settings.cors_origins()` ではなく `settings.cors_origins` と、`()` なしで値のように読める |
| `def cors_origins(self) -> list[str]:` | メソッドの定義。`self` は「この Settings 自身」。`-> list[str]` は「文字列のリストを返す」という型の注釈 |
| `return [origin.strip() for origin in self.cors_allow_origins.split(",") if origin.strip()]` | リスト内包表記という書き方。真ん中から読む:① `split(",")` でカンマごとに分ける → ② 1 つずつ `origin` に入れる → ③ `if origin.strip()` で空のものを除く → ④ 前後の空白を除いた `origin.strip()` を集めてリストにする |
| `@lru_cache` | 次の関数の結果を覚えておく印。2 回目以降は、中身を実行せずに 1 回目の結果を返す |
| `def get_settings() -> Settings:` | 設定を返す関数。戻り値の型は `Settings` |
| `return Settings()` | `Settings` を作る。**この瞬間に** 環境変数と `.env` が読まれ、必須・制約のチェックが行われる。NG なら `ValidationError` |

</details>

✅ 確認:次のコマンドで、`.env` の値が読めているかを確かめる

### STEP 6:`app/routers/health.py` を作る

📘 設計:詳細設計書 5.2

`app/routers/health.py` を新規作成し、次の内容を書く。

```python
"""ヘルスチェック API。"""

from typing import Literal

from fastapi import APIRouter
from pydantic import BaseModel

router = APIRouter(tags=["health"])


class HealthResponse(BaseModel):
    status: Literal["ok"]


@router.get("/health", response_model=HealthResponse)
def health() -> HealthResponse:
    """API が応答できるかを返す。認証不要。DB 等の外部サービスには接続しない。"""
    return HealthResponse(status="ok")
```

<details>
<summary>🔰 1行ずつの解説(クリックで開く)</summary>

| コード | 何をしているか |
| --- | --- |
| `"""ヘルスチェック API。"""` | ファイルの説明文 |
| `from typing import Literal` | 「決まった値だけを入れてよい」という型 `Literal` を読み込む |
| `from fastapi import APIRouter` | API の窓口(エンドポイント)をまとめる入れ物 `APIRouter` を読み込む |
| `from pydantic import BaseModel` | 応答の形を定義するときの元になるクラスを読み込む |
| `router = APIRouter(tags=["health"])` | ルーターを作る。`tags` は `/docs` の画面でのグループ名 |
| `class HealthResponse(BaseModel):` | 応答の形を表すクラス。`BaseModel` を引き継ぐと、型のチェックと JSON への変換ができるようになる |
| `status: Literal["ok"]` | 項目 `status` には `"ok"` という文字列だけが入る |
| `@router.get("/health", response_model=HealthResponse)` | 次の関数を `GET /health` の窓口にする印。応答は `HealthResponse` の形で返す(`/docs` にもこの形が載る) |
| `def health() -> HealthResponse:` | 窓口の本体の関数。関数名は自由に付けてよい |
| `"""API が応答できるかを返す。…"""` | 関数の説明文。`/docs` の画面にも表示される |
| `return HealthResponse(status="ok")` | 応答を作って返す。FastAPI が JSON の `{"status": "ok"}` に変換してブラウザに返す |

</details>

✅ 確認:この時点ではまだ起動できない(`main.py` がないため)。次の STEP へ進む

📚 公式:[APIRouter](https://fastapi.tiangolo.com/tutorial/bigger-applications/#apirouter)・[response_model](https://fastapi.tiangolo.com/tutorial/response-model/)

### STEP 7:`app/main.py` を作る

📘 設計:詳細設計書 5.3・5.4

`app/main.py` を新規作成し、次の内容を書く。

```python
"""FastAPI アプリの組み立て(設定の読み込み・CORS・ルーターの登録)。"""

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.config import get_settings
from app.routers import health

settings = get_settings()

app = FastAPI(title="jelgram API", version="0.1.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,
    allow_methods=["GET", "POST", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
    allow_credentials=False,
)

app.include_router(health.router)
```

- 変数名は必ず `app` にする(起動コマンドが `app` という名前の変数を探すため)
- CORS の設定値の理由は、詳細設計書 5.4 の表を参照

<details>
<summary>🔰 1行ずつの解説(クリックで開く)</summary>

| コード | 何をしているか |
| --- | --- |
| `from fastapi import FastAPI` | アプリ本体のクラス `FastAPI` を読み込む |
| `from fastapi.middleware.cors import CORSMiddleware` | CORS の処理をしてくれる部品(ミドルウェア)を読み込む |
| `from app.config import get_settings` | STEP 5 で作った、設定を返す関数を読み込む |
| `from app.routers import health` | STEP 6 で作った `app/routers/health.py` を、`health` という名前で読み込む |
| `settings = get_settings()` | 設定を読む。ここで `.env` がチェックされるので、設定漏れがあると起動時にエラーになる |
| `app = FastAPI(title="jelgram API", version="0.1.0")` | アプリを作る。`title`・`version` は `/docs` の画面の見出しに表示される |
| `app.add_middleware(` | アプリにミドルウェアを追加する。ミドルウェアは、すべてのリクエストの前後に共通の処理を挟むしくみ |
| `CORSMiddleware,` | 追加するのは CORS の処理 |
| `allow_origins=settings.cors_origins,` | 許可するオリジンのリスト(例:`["http://localhost:3000"]`) |
| `allow_methods=["GET", "POST", "DELETE"],` | 許可する HTTP メソッド |
| `allow_headers=["Authorization", "Content-Type"],` | ブラウザがリクエストに付けてよいヘッダー |
| `allow_credentials=False,` | Cookie を送ることを許可しない(認証は Cookie ではなくヘッダーで行うため) |
| `app.include_router(health.router)` | `health.py` の `router` をアプリに登録する。これで `GET /health` が使えるようになる |

</details>

📚 公式:[FastAPI の基本形](https://fastapi.tiangolo.com/ja/tutorial/first-steps/)・[CORS](https://fastapi.tiangolo.com/ja/tutorial/cors/)・[include_router](https://fastapi.tiangolo.com/tutorial/bigger-applications/)

**① `tests/conftest.py`(テスト共通の準備)**

```python
"""テスト共通の準備。

app.main は import された時点で設定を読むため、テスト用のダミー値を
import より前に環境変数へ設定する(環境変数は .env より優先されるため、本物のキーは使われない)。
"""

import os

os.environ["SUPABASE_URL"] = "https://test.supabase.co"
os.environ["SUPABASE_SECRET_KEY"] = "test-secret-key"
os.environ["DATABASE_URL"] = "postgresql://test:test@localhost:5432/test"
os.environ["GEMINI_API_KEY"] = "test-gemini-key"
os.environ["CORS_ALLOW_ORIGINS"] = "http://localhost:3000"

import pytest  # noqa: E402
from fastapi.testclient import TestClient  # noqa: E402

from app.main import app  # noqa: E402


@pytest.fixture
def client() -> TestClient:
    return TestClient(app)
```

- `os.environ[...] = ...` は、必ず `from app.main import app` より **前** に書く(詳細設計書 7.1 のつまずきポイント)
- `# noqa: E402` は、「import がファイルの先頭にない」という Ruff の指摘を、この行だけ止める印

**② `tests/test_health.py`(T-01〜T-03)**

```python
"""ヘルスチェック・CORS のテスト(詳細設計書 7.2 T-01〜T-03)。"""

from fastapi.testclient import TestClient


def test_health_returns_ok(client: TestClient) -> None:
    """T-01: 認証ヘッダーなしで 200 と {"status": "ok"} が返る。"""
    response = client.get("/health")

    assert response.status_code == 200
    assert response.json() == {"status": "ok"}


def test_cors_preflight_from_allowed_origin(client: TestClient) -> None:
    """T-02: 許可したオリジンからのプリフライトが通る。"""
    response = client.options(
        "/health",
        headers={
            "Origin": "http://localhost:3000",
            "Access-Control-Request-Method": "GET",
        },
    )

    assert response.status_code == 200
    assert response.headers["access-control-allow-origin"] == "http://localhost:3000"


def test_cors_not_allowed_for_unknown_origin(client: TestClient) -> None:
    """T-03: 許可していないオリジンには CORS 許可のヘッダーを返さない。"""
    response = client.get("/health", headers={"Origin": "http://evil.example.com"})

    assert "access-control-allow-origin" not in response.headers
```

- 引数に `client` と書くと、conftest.py の fixture `client` が自動で渡される

```python
_env_file=None を渡して、ローカルの .env を読まずに Settings を生成する。
"""

import pytest
from pydantic import ValidationError

from app.config import Settings

REQUIRED = {
    "supabase_url": "https://test.supabase.co",
    "supabase_secret_key": "test-secret-key",
    "database_url": "postgresql://test:test@localhost:5432/test",
    "gemini_api_key": "test-gemini-key",
}


def test_cors_origins_splits_comma_separated_string() -> None:
    """T-04: カンマ区切りを分割し、前後の空白と空の要素を除く。"""
    settings = Settings(
        _env_file=None, **REQUIRED, cors_allow_origins="http://a.com, http://b.com,"
    )

    assert settings.cors_origins == ["http://a.com", "http://b.com"]


def test_empty_required_value_raises_error() -> None:
    """T-05: 必須項目が空文字だとエラーになる。"""
    with pytest.raises(ValidationError):
        Settings(_env_file=None, **{**REQUIRED, "gemini_api_key": ""})


def test_defaults_are_applied() -> None:
    """T-06: 省略した項目に初期値が入る。"""
    settings = Settings(_env_file=None, **REQUIRED)

    assert settings.gemini_model == "gemini-3.5-flash-lite"
    assert settings.rate_limit_global_per_day == 400


def test_rate_limit_must_be_positive() -> None:
    """T-07: レート制限に 0 以下を指定するとエラーになる。"""
    with pytest.raises(ValidationError):
```

<summary>🔰 1行ずつの解説(クリックで開く)</summary>

| コード | 何をしているか |
| --- | --- |
| `from pydantic import ValidationError` | 値のチェックに失敗したときに出るエラーの種類を読み込む |
| `from app.config import Settings` | テストする対象の `Settings` クラスを読み込む |
| `REQUIRED = { … }` | 必須項目のダミー値をまとめた辞書。名前を全部大文字にするのは「途中で変えない値(定数)」という慣習 |
| `settings = Settings(` | 設定を直接作る(`get_settings()` を使わない) |
| `_env_file=None,` | `.env` を読まない指定。自分の `.env` の中身にテスト結果が左右されないようにする |
| `**REQUIRED,` | 辞書を「キー=値」の引数に展開する。`supabase_url="…", supabase_secret_key="…", …` と書いたのと同じ |
| `cors_allow_origins="http://a.com, http://b.com,"` | テストしたい値。空白と末尾のカンマをわざと入れている |
| `assert settings.cors_origins == ["http://a.com", "http://b.com"]` | 分割・空白の除去・空の要素の除去ができているか |
| `with pytest.raises(ValidationError):` | この中で `ValidationError` が出れば成功、出なければ失敗 |
| `Settings(_env_file=None, **{**REQUIRED, "gemini_api_key": ""})` | `{**REQUIRED, "gemini_api_key": ""}` は「`REQUIRED` をコピーして、`gemini_api_key` だけ空文字に上書きした辞書」。空文字なのでエラーになるはず |
| `settings = Settings(_env_file=None, **REQUIRED)` | 必須項目だけを渡して作る |
| `assert settings.gemini_model == "gemini-3.5-flash-lite"` | 渡していない項目に初期値が入っているか |
| `assert settings.rate_limit_global_per_day == 400` | 同上 |
| `Settings(_env_file=None, **REQUIRED, rate_limit_per_user_per_minute=0)` | 0(1 未満)を入れて作る。`ge=1` の制約でエラーになるはず |

## 困ったときは

| 症状                                                               | 原因と対処                                                                                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `ModuleNotFoundError: No module named 'app'`                       | `apps/api` 以外の場所で実行している。`pwd` で場所を確認し、`apps/api` に移動する。テストの場合は STEP 3 の `pythonpath` の設定を確認 |
| 起動時に `ValidationError` と `Field required` が出る              | `.env` に必須項目が書かれていない。エラーに出ているフィールド名を `.env` で確認する                          |
| 起動時に `String should have at least 1 character` が出る          | `.env` の必須項目の値が空。値を入れる                                                                        |
| `Address already in use`                                           | 別のターミナルでサーバーが起動したまま。そちらを `Ctrl + C` で止める                                        |
| `fastapi: command not found`                                       | `uv run` を付け忘れている。`uv run fastapi dev app/main.py` のように実行する                                 |
| テストで本物の `.env` の値が使われてしまう                         | conftest.py で、環境変数の設定が `import` より後になっている(詳細設計書 7.1 のつまずきポイント)            |
| Ruff が `E402 Module level import not at top of file` を出す       | conftest.py の意図的な書き方によるもの。その import 行の末尾に `# noqa: E402` を付ける                       |
| T-02 で `400` が返る                                               | `allow_methods` か `allow_origins` の設定が STEP 7 のコードと違う                                           |
| `warning: VIRTUAL_ENV=... does not match the project environment path .venv` | 別の仮想環境(pyenv 等)が有効になったターミナルで実行している。uv は自動でプロジェクトの `.venv` を使うので動作に問題はない。気になる場合は `deactivate` するか、新しいターミナルで実行する |
| テスト実行時に `StarletteDeprecationWarning: ... install httpx2 instead` | `httpx2` が入っていない。`uv add --dev httpx2` を実行する |
| VS Code で import に赤い波線が出る                                 | VS Code が `.venv` の Python を使っていない。`Cmd + Shift + P` →「Python: Select Interpreter」→ `apps/api/.venv` を選ぶ |
