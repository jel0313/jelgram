### STEP 3:`app/core/db.py` を作り、DB に接続できるか確かめる

📘 設計:詳細設計書 3章・6.2

`app/core/db.py` を新規作成し、次の内容を書く。

```python
"""DB 接続(エンジン・セッション)。"""

from collections.abc import Iterator
from functools import lru_cache
from typing import Annotated

from fastapi import Depends
from sqlalchemy import create_engine
from sqlalchemy.engine import Engine
from sqlalchemy.orm import Session

from app.core.config import get_settings


@lru_cache
def get_engine() -> Engine:
    """エンジン(コネクションプール)を返す。アプリ全体で1つを使い回す。"""
    settings = get_settings()
    return create_engine(settings.sqlalchemy_database_url, pool_pre_ping=True)


def get_db() -> Iterator[Session]:
    """リクエストごとに DB セッションを渡し、終わったら閉じる(接続をプールに返す)。"""
    with Session(get_engine()) as session:
        yield session


DbSessionDep = Annotated[Session, Depends(get_db)]
```

<details>
<summary>🔰 1行ずつの解説(クリックで開く)</summary>

| コード | 何をしているか |
| --- | --- |
| `from collections.abc import Iterator` | `yield` する関数の戻り値の型 |
| `from functools import lru_cache` | 関数の結果を覚えておく道具 |
| `from typing import Annotated` | 「型 + `Depends(...)`」をまとめて書く道具(4.2 の `CurrentUserDep` と同じ) |
| `from fastapi import Depends` | 依存関数を指定する |
| `from sqlalchemy import create_engine` | エンジン(接続の置き場 = プールを持つもの)を作る関数 |
| `from sqlalchemy.engine import Engine` | エンジンの型 |
| `from sqlalchemy.orm import Session` | セッション(DB との 1 回分の会話)のクラス。生の SQL の実行と、確定・取り消し(トランザクション)を受け持つ |
| `from app.core.config import get_settings` | 設定を返す関数 |
| `@lru_cache` | 結果を覚えておく印。これでエンジン(= プール)がアプリ全体で 1 つだけになる |
| `def get_engine() -> Engine:` | エンジンを返す関数 |
| `settings = get_settings()` | 設定を読む |
| `return create_engine(settings.sqlalchemy_database_url, pool_pre_ping=True)` | STEP 2 で作った接続文字列でエンジンを作る。`pool_pre_ping=True` は「接続を借りる前に、まだつながっているか確かめる」。この時点ではまだ DB に接続しない(最初に SQL を実行したときに接続する) |
| `def get_db() -> Iterator[Session]:` | リクエストごとにセッションを渡す依存関数 |
| `with Session(get_engine()) as session:` | セッションを作る。`with` のブロックを抜けると、セッションが自動で閉じて接続がプールに返る |
| `yield session` | エンドポイントにセッションを渡して、ここで一時停止する。エンドポイントの処理が終わると続きから再開し、`with` を抜けて片付けが行われる(エラーのときも必ず片付く) |
| `DbSessionDep = Annotated[Session, Depends(get_db)]` | 「`get_db` が渡すセッション」を 1 語で書ける別名。各 API は `session: DbSessionDep` と書くだけでよい |

</details>

### STEP 6:DB アクセスを作る(`posts/repository.py`)

📘 設計:詳細設計書 6.3・6.4.3

`app/posts/repository.py` を新規作成し、次の内容を書く。

```python
"""投稿・いいねの DB アクセス。SQL はこのファイルにだけ書く。

SQL は text() で生のまま書き、値は必ずバインド変数(:post_id など)で渡す。
確定(commit)はしない。確定は service が行う。
"""

from uuid import UUID

from sqlalchemy import Row, text
from sqlalchemy.orm import Session

# 投稿・投稿者・いいね数・自分がいいね済みか を 1 回で取る SELECT。WHERE・ORDER BY は各関数で足す
_SELECT_POSTS = """
    select
        p.id,
        p.content,
        p.image_url,
        p.created_at,
        pr.id           as author_id,
        pr.display_name as author_display_name,
        pr.avatar_url   as author_avatar_url,
        (select count(*) from likes l where l.post_id = p.id) as like_count,
        exists (
            select 1 from likes l where l.post_id = p.id and l.user_id = :user_id
        ) as liked_by_me
    from posts p
    join profiles pr on pr.id = p.user_id
"""


def find_timeline(session: Session, user_id: UUID, limit: int) -> list[Row]:
    """新しい順(同じ時刻なら id の大きい順)に、最大 limit 件を取る。"""
    sql = text(_SELECT_POSTS + "order by p.created_at desc, p.id desc limit :limit")
    return list(session.execute(sql, {"user_id": user_id, "limit": limit}).all())


def find_post_row(session: Session, post_id: int, user_id: UUID) -> Row:
    """投稿 1 件を、タイムラインと同じ形で取る。"""
    sql = text(_SELECT_POSTS + "where p.id = :post_id")
    return session.execute(sql, {"user_id": user_id, "post_id": post_id}).one()


def exists_post(session: Session, post_id: int) -> bool:
    sql = text("select exists (select 1 from posts where id = :post_id)")
    return session.execute(sql, {"post_id": post_id}).scalar_one()


def insert_post(session: Session, user_id: UUID, content: str, image_url: str | None) -> int:
    """投稿を追加し、DB が振った id を返す(確定はしない)。"""
    sql = text(
        "insert into posts (user_id, content, image_url) "
        "values (:user_id, :content, :image_url) "
        "returning id"
    )
    params = {"user_id": user_id, "content": content, "image_url": image_url}
    return session.execute(sql, params).scalar_one()


def insert_like(session: Session, post_id: int, user_id: UUID) -> None:
    """いいねを追加する。すでにあれば何もしない。"""
    sql = text(
        "insert into likes (user_id, post_id) values (:user_id, :post_id) "
        "on conflict (user_id, post_id) do nothing"
    )
    session.execute(sql, {"user_id": user_id, "post_id": post_id})


def delete_like(session: Session, post_id: int, user_id: UUID) -> None:
    """いいねを削除する。なければ何もしない。"""
    sql = text("delete from likes where user_id = :user_id and post_id = :post_id")
    session.execute(sql, {"user_id": user_id, "post_id": post_id})


def count_likes(session: Session, post_id: int) -> int:
    sql = text("select count(*) from likes where post_id = :post_id")
    return session.execute(sql, {"post_id": post_id}).scalar_one()


def is_liked(session: Session, post_id: int, user_id: UUID) -> bool:
    sql = text(
        "select exists (select 1 from likes where post_id = :post_id and user_id = :user_id)"
    )
    return session.execute(sql, {"post_id": post_id, "user_id": user_id}).scalar_one()
```

<details>
<summary>🔰 1行ずつの解説(クリックで開く)</summary>

**読み込み**

| コード | 何をしているか |
| --- | --- |
| `from sqlalchemy import Row, text` | `Row`:SQL の結果の 1 行の型。`text`:生の SQL を「実行できる SQL」に包む関数 |
| `from sqlalchemy.orm import Session` | セッションの型 |

**`_SELECT_POSTS`:1 回の SQL で必要なものを全部取る**

| コード | 何をしているか |
| --- | --- |
| `_SELECT_POSTS = """ … """` | 投稿を取る SELECT 文(文字列)。`"""` で囲むと、改行を含む文字列を書ける。先頭の `_` は「このファイルの中だけで使う」、全部大文字は「定数(書き換えない値)」の印 |
| `p.id, p.content, p.image_url, p.created_at,` | 投稿の列。`p` は `posts` の別名(下の `from posts p`) |
| `pr.id as author_id,` など 3 行 | 投稿者の列。`pr` は `profiles` の別名。`posts` にも `id` があるので、`as author_id` で名前を変えてぶつからないようにする |
| `(select count(*) from likes l where l.post_id = p.id) as like_count,` | 「この投稿の likes の件数」を数える小さな SQL(サブクエリ)。外側の行ごとに実行される |
| `exists (select 1 from likes l where l.post_id = p.id and l.user_id = :user_id) as liked_by_me` | 「この投稿に、自分のいいねがあるか」。あれば true、なければ false。`:user_id` はバインド変数(値は後で渡す) |
| `from posts p` / `join profiles pr on pr.id = p.user_id` | posts と profiles を「投稿の `user_id` = プロフィールの `id`」でつなぐ(JOIN) |

**取得する関数**

| コード | 何をしているか |
| --- | --- |
| `sql = text(_SELECT_POSTS + "order by p.created_at desc, p.id desc limit :limit")` | 共通の SELECT の後ろに、並び順と件数を足す。`desc` は大きい順(新しい順)。同じ時刻なら id の大きい順。つなげているのは固定の文字列だけで、値は `:limit` で渡す |
| `return list(session.execute(sql, {"user_id": user_id, "limit": limit}).all())` | SQL を実行する。2 つ目の辞書が、`:user_id`・`:limit` に入る値。`.all()` で全行を受け取り、リストにして返す |
| `sql = text(_SELECT_POSTS + "where p.id = :post_id")` | 共通の SELECT に、投稿 ID の条件を足す |
| `return session.execute(sql, {"user_id": user_id, "post_id": post_id}).one()` | ちょうど 1 行を受け取る(`.one()`) |
| `sql = text("select exists (select 1 from posts where id = :post_id)")` | 投稿があるかを true / false で返す SQL |
| `return session.execute(sql, {"post_id": post_id}).scalar_one()` | 結果の値を 1 つだけ受け取る(`.scalar_one()`) |

**追加・削除する関数**

| コード | 何をしているか |
| --- | --- |
| `sql = text("insert into posts (user_id, content, image_url) " "values (…) " "returning id")` | 投稿を 1 行追加する SQL。文字列を並べて書くと、Python が 1 つにつなげる(つなぎ目の空白を忘れない)。`returning id` は「追加した行の id を返して」 |
| `params = {"user_id": user_id, "content": content, "image_url": image_url}` | SQL に入れる値。`image_url` が `None` なら、DB には NULL が入る |
| `return session.execute(sql, params).scalar_one()` | 実行して、DB が振った id を受け取って返す。**確定はしない**(確定は service) |
| `"on conflict (user_id, post_id) do nothing"` | 「すでに同じ `(user_id, post_id)` の行(主キー)があれば何もしない」。だから 2 回押してもエラーにならない |
| `sql = text("delete from likes where user_id = :user_id and post_id = :post_id")` | 自分のいいねを削除する。もともとなければ何も起きない |

**数える関数**

| コード | 何をしているか |
| --- | --- |
| `sql = text("select count(*) from likes where post_id = :post_id")` | この投稿の likes を数える |
| `select exists (select 1 from likes where post_id = :post_id and user_id = :user_id)` | 自分のいいねがあるかを true / false で返す |

```python
"""投稿・いいねの業務ロジック。

入力のチェック・DB の確定(commit)・応答の形への詰め替えを行う。SQL は repository に任せる。
"""

from uuid import UUID

from sqlalchemy import Row
from sqlalchemy.orm import Session

from app.core.config import Settings
from app.posts import repository
from app.posts.constants import TIMELINE_LIMIT
from app.posts.exceptions import InvalidImageUrlError, PostNotFoundError
from app.posts.schemas import AuthorResponse, LikeResponse, PostCreate, PostResponse


def _to_post_response(row: Row) -> PostResponse:
    """repository の 1 行を応答の形にする(author_ で始まる列が投稿者)。"""
    return PostResponse(
        id=row.id,
        content=row.content,
        image_url=row.image_url,
        created_at=row.created_at,
        author=AuthorResponse(
            id=row.author_id,
            display_name=row.author_display_name,
            avatar_url=row.author_avatar_url,
        ),
        like_count=row.like_count,
        liked_by_me=row.liked_by_me,
    )


def _ensure_post_exists(session: Session, post_id: int) -> None:
    if not repository.exists_post(session, post_id):
        raise PostNotFoundError()


def _like_response(session: Session, post_id: int, user_id: UUID) -> LikeResponse:
    return LikeResponse(
        post_id=post_id,
        like_count=repository.count_likes(session, post_id),
        liked_by_me=repository.is_liked(session, post_id, user_id),
    )


def get_timeline(session: Session, user_id: UUID) -> list[PostResponse]:
    rows = repository.find_timeline(session, user_id, TIMELINE_LIMIT)
    return [_to_post_response(row) for row in rows]


def create_post(
    session: Session, user_id: UUID, body: PostCreate, settings: Settings
) -> PostResponse:
    """投稿する。画像は自分の Storage バケットの URL だけを受け付ける。"""
    bucket_url = (
        f"{settings.supabase_url}/storage/v1/object/public/{settings.supabase_storage_bucket}/"
    )
    if body.image_url is not None and not body.image_url.startswith(bucket_url):
        raise InvalidImageUrlError()

    post_id = repository.insert_post(session, user_id, body.content, body.image_url)
    session.commit()
    return _to_post_response(repository.find_post_row(session, post_id, user_id))


def like_post(session: Session, post_id: int, user_id: UUID) -> LikeResponse:
    """いいねする。いいね済みなら何もしない。"""
    _ensure_post_exists(session, post_id)
    repository.insert_like(session, post_id, user_id)
    session.commit()
    return _like_response(session, post_id, user_id)


def unlike_post(session: Session, post_id: int, user_id: UUID) -> LikeResponse:
    """いいねを取り消す。いいねしていなければ何もしない。"""
    _ensure_post_exists(session, post_id)
    repository.delete_like(session, post_id, user_id)
    session.commit()
    return _like_response(session, post_id, user_id)
```

```python
    return service.like_post(session, post_id, user.id)

def unlike_post(post_id: int, user: CurrentUserDep, session: DbSessionDep) -> LikeResponse:
```

| `from sqlalchemy.orm import Session` | セッションのクラス |
| `from app.auth.dependencies import get_current_user` / `from app.auth.schemas import CurrentUser` | ログインの差し替えに使う |
| `from app.core.db import get_db, get_engine` | DB セッションの差し替えと、テスト用の接続に使う |

**`db_session`:最後に全部取り消すセッション**

| コード | 何をしているか |
| --- | --- |
| `def db_session() -> Iterator[Session]:` | テストごとに新しく作られる fixture |
| `connection = get_engine().connect()` | DB に接続する |
| `transaction = connection.begin()` | トランザクションを始める。この後の変更は、確定(コミット)するまで仮の状態 |
| `session = Session(bind=connection, join_transaction_mode="create_savepoint")` | この接続の上でセッションを作る。`create_savepoint` にすると、API の中で `session.commit()` を呼んでも「途中の区切り(セーブポイント)」の確定になり、外側のトランザクションは確定しない |
| `yield session` | ここでテスト本体が実行される |
| `session.close()` | セッションを閉じる |
| `transaction.rollback()` | トランザクションを取り消す。テスト中に作ったユーザー・投稿・いいねが全部消える |
| `connection.close()` | 接続を閉じる |

**`db_client`:DB を差し替えた TestClient**

| コード | 何をしているか |
| --- | --- |
| `def db_client(db_session: Session) -> Iterator[TestClient]:` | 上の `db_session` を受け取る |
| `app.dependency_overrides[get_db] = lambda: db_session` | 「`get_db` の代わりに、`db_session` を返す関数を使って」と登録する。これで API が、取り消されるセッションを使うようになる |
| `yield TestClient(app)` | TestClient を渡して、テスト本体を実行する |
| `app.dependency_overrides.clear()` | テストが終わったら差し替えを全部戻す(`login_as` の差し替えもここで戻る) |

**`create_user`:テスト用ユーザーを作る関数**

| コード | 何をしているか |
| --- | --- |
| `def create_user(db_session: Session) -> Callable[..., UUID]:` | 「UUID を返す関数」を返す fixture |
| `def _create_user(display_name: str = "テストユーザー") -> UUID:` | 表示名を受け取ってユーザーを作る関数。省略したら「テストユーザー」 |
| `user_id = uuid4()` | ランダムなユーザー ID を作る |
| `db_session.execute(` | SQL を実行する |
| `text("insert into auth.users (id, email, raw_user_meta_data) " "values (…)")` | Supabase のユーザー表(`auth.users`)に 1 行入れる SQL。`:id`・`:email`・`:name` は、下の辞書の値が安全に埋め込まれる場所。2 つの文字列を並べると、Python が 1 つの文字列につなげる |
| `jsonb_build_object('full_name', cast(:name as text))` | `{"full_name": "表示名"}` という JSON を作る SQL。トリガーがこれを `profiles.display_name` に使う |
| `{"id": user_id, "email": f"{user_id}@example.com", "name": display_name},` | SQL に埋め込む値。メールアドレスは ID を使って、他と重ならないようにする |
| `return user_id` | 作ったユーザーの ID を返す |
| `return _create_user` | 関数そのものを返す |

**`login_as`:ログインの差し替え**

| コード | 何をしているか |
| --- | --- |
| `def _login_as(user_id: UUID) -> None:` | ユーザー ID を受け取る関数 |
| `user = CurrentUser(id=user_id, email=f"{user_id}@example.com")` | ログイン中のユーザーを作る |
| `app.dependency_overrides[get_current_user] = lambda: user` | 「`get_current_user` の代わりに、このユーザーを返す関数を使って」と登録する。トークンの検証をせずに、このユーザーでログインしていることになる |

</details>

## 困ったときは

| 症状                                                                                  | 原因と対処                                                                                                                                         |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ModuleNotFoundError: No module named 'psycopg2'`                                     | 接続文字列が `postgresql://` のまま。`create_engine` に `sqlalchemy_database_url`(`+psycopg` 付き)を渡しているか確認                             |
| 接続時に `connection timeout` や `could not translate host name`                      | 開発用の Supabase が一時停止している、またはネットワークの問題。管理画面でプロジェクトを開き、停止中なら再開する                                   |
| 接続時に `password authentication failed`                                             | `.env` の `DATABASE_URL` のパスワードが違う。再発行した場合は書き換え忘れがないか確認                                                               |
| `Port could not be cast to integer` / 接続文字列の解析エラー                           | DB のパスワードに記号(`?` `/` `@` など)が入っている。英数字だけのパスワードに再発行する                                                          |
| `POST /posts` で `500` と `ForeignKeyViolation`                                        | ログイン中のユーザーの `profiles` がない。3.2 のトリガーが動いているか、Table Editor の `profiles` で確認する                                      |
| `psycopg.errors.UndefinedColumn: column … does not exist` / `UndefinedTable`         | SQL の列名・テーブル名のタイプミス。`supabase/migrations/20260928000000_initial_schema.sql` と見比べる                                              |
| `psycopg.errors.SyntaxError: syntax error at or near …`                              | 文字列を並べて書いた SQL の、つなぎ目の空白が抜けている(例:`"… from likes" "where …"` だと `likeswhere` になる)。各行の末尾に空白があるか確認する |
| `A value is required for bind parameter 'user_id'`                                    | SQL の `:user_id` に対応する値が辞書にない。`session.execute(sql, {…})` の辞書のキーと、SQL の `:名前` を見比べる                                   |
| `AttributeError: Could not locate column in row for column 'author_id'`               | `select` の `as author_id` の別名が抜けている、または綴りが違う。service の `row.〇〇` と SQL の列名を見比べる                                      |
| いいねを 2 回押すと `500` と `UniqueViolation`                                        | `insert_like` の SQL に `on conflict (user_id, post_id) do nothing` がない                                                                          |
| T-04 がたまに失敗する                                                                 | 並び順に `p.id desc` がない(詳細設計書 8.1 のつまずきポイント)                                                                                   |
| テスト用ユーザーが DB に残っている(STEP 12 の SQL が 0 にならない)                  | `db_session` の片付けで `transaction.rollback()` していない、または `db_client` ではなく `client` で投稿している。Table Editor で残ったユーザーを削除してから直す |
| `test_posts.py` だけなら通るのに、全部まとめて実行すると失敗する                      | 差し替えを戻していない。`db_client` の `yield` の後で `app.dependency_overrides.clear()` する                                                      |
| テストで `ValidationError` と `database_url` が出る                                   | conftest.py から `DATABASE_URL` の行を消したのに、`.env` に `DATABASE_URL` がない。`.env` を確認する                                              |
| Ruff の format で `core/config.py` が直される                                              | STEP 2 で足したプロパティの前の空行が 2 行になっている。`ruff format` が 1 行に直すので、そのままでよい                                             |
| `/docs` で `post_id` に数字以外を入れると `422`                                       | 正常。パスの `post_id: int` を FastAPI が自動でチェックしている                                                                                    |
