# 不具合管理表

フェーズ1(アプリ完成)の製造・テストで見つかった不具合。再発防止は、チェックリストやテストに反映したものを書く。

| ID | 発見工程 | 現象 | 原因 | 対策 | 再発防止 |
|---|---|---|---|---|---|
| B-001 | IT | ハッシュタグ付きの投稿が 500 | `unnest(:tags)` の配列の型を PostgreSQL が決められない(AmbiguousFunction) | `cast(:tags as text[])` を付ける | 配列・null になりうるバインド変数には必ず cast を書く(カーソルの `:cursor_t` も同じ対応) |
| B-002 | UT | Content-Length なしの大きな本文が 413 ではなく 400 | FastAPI が本文の読み込み中の例外を 400 に変換してしまう | 上限を超えたら、アプリの応答を捨てて 413 に置き換える | chunked 送信の UT を追加(UT_基盤と認証 No.16) |
| B-003 | IT | ワーカーが同じイベントを何度も処理する | 各処理が自分で commit し、Outbox の「処理済み」とずれた | 確定は relay_outbox だけが行う | handlers.py の冒頭に方針を明記。IT で「2回目は 0 件」を確認 |
| B-004 | 動作確認 | フォローのメールが届かない(フォロー自体は成功) | Supabase の設定で SMTP のポートを開けた後、再起動していなかった | `supabase stop` → `supabase start` | README の困ったときはに追記 |
| B-005 | ST | シードのユーザーでログインすると Supabase Auth が 500 | auth.users のトークン系の列が NULL・identities がない | 空文字を入れ、identities にも行を作る | seed.py にコメントで理由を残す |
| B-006 | IT | 開発で使った後だと、一部の IT が失敗する | テストが DB の既存データ(シード・残った Outbox)に依存していた | 自分で作ったデータだけを見る。Outbox はテストの間だけ処理済みにする | IT は「空の DB」を前提にしない(テストのレビュー観点に追加) |
| B-007 | UT | .env.example をコピーすると Sentry・METRICS_TOKEN が空文字で有効になる | `SecretStr \| None` は空文字を None にしない | 空文字を None に変換する検証を追加 | UT_基盤と認証 No.7 |
