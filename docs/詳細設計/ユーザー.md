# 詳細設計:ユーザー・フォロー・ブロック・退会(第1・2・7・13・21章)

対象:`app/users/`

## 処理フロー

### プロフィールの取得(キャッシュアサイド。13-1)

```
ユーザー名 → id(ブロック関係なら 404)
Redis の cache:profile:v1:<id> にある → それを使う
ない → DB(件数の集計込み)→ Redis に 300 秒保存
閲覧者との関係(フォロー状態・ブロック)は毎回 DB(人によって違うのでキャッシュしない)
```
更新・フォロー・ブロックのたびに、関係する人のキャッシュを消す(13-2)。

### フォロー(7-3)

```
自分 → 400 / 相手が非公開 → pending(通知:follow_request)/ 公開 → accepted(通知:follow)
初めてのフォローなら、相手にメール(BackgroundTasks。応答の後に送る)
承認:行ロック(select … for update)→ accepted → 通知(follow_accepted)
非公開をやめる → pending を全部 accepted
```

### ブロック(7-4)

```
insert blocks → お互いのフォローを削除
以後:プロフィール・投稿・コメント・いいね・通知が、どちら向きにも見えない(core/visibility.py)
```

### 退会(21-2)

```
1 トランザクションで:
  プロフィールを匿名化(status = deleted・username = deleted_xxx・表示名「退会したユーザー」)
  投稿を論理削除・いいね(カウンタを戻してから)・フォロー・チャット・画像の行を削除
  Outbox:media.delete(ファイル)・user.purge(Supabase Auth のユーザー削除)・監査ログ
ワーカー:Auth の管理 API で削除 → profiles 以下が cascade で物理削除
```

## 関数一覧

| 関数 | 役割 |
|---|---|
| get_profile・get_me・update_profile・update_avatar | プロフィール |
| search_users | ユーザー名・表示名の部分一致 |
| follow・unfollow・answer_follow_request・list_follow_requests・list_follow_users | フォロー |
| block・unblock・list_blocks | ブロック |
| delete_account・export_account | 退会・エクスポート(21-3) |

## SQL(抜粋)

```sql
-- 承認待ちに行ロック(10-3)
select 1 from follows where follower_id = :a and followee_id = :b and status = 'pending' for update

-- ユーザー名の重複は一意制約で判定(先に select で調べると、同時登録で両方通る)
update profiles set username = :username where id = :id   -- → IntegrityError → 409
```

## 入力チェック(1-3・1-4)

| 項目 | ルール |
|---|---|
| username | 小文字にしてから `^[a-z0-9_]{3,30}$`・予約語(admin・me など)は不可 |
| display_name | 1〜50 字 |
| bio | 150 字まで |
| PATCH の本文 | 1 項目以上・null は不可・余計な項目は 422 |
| email(応答) | EmailStr。本人の /me にだけ入る(1-5) |
