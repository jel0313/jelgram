# 詳細設計:認証・認可(第6・7章)

対象:`app/auth/`。方式は [認証認可方式](../基本設計/認証認可方式.md)。

## 処理フロー:get_current_user

```
Bearer がない → 401 unauthorized
  ↓ decode_token
JWKS で鍵を取る
  ├ 接続できない → 503
  └ kid が合わない → 401 invalid_token
jwt.decode(algorithms=["ES256"], audience, issuer, require=[exp, sub, aud, iss])
  └ 失敗 → 401 invalid_token
  ↓
session_id が Redis の revoked_session:<id> にある → 401(ログアウト済み)
  ↓
repository.get_account(user_id)
  ├ ない・deleted → 401
  └ suspended → 403 account_suspended
  ↓
CurrentUser(id・email・role・session_id・expires_at)
```

## 関数一覧

| 関数 | 入力 | 出力 | 例外 |
|---|---|---|---|
| decode_token(token, jwks, settings) | JWT 文字列 | クレーム | InvalidTokenError・ServiceUnavailableError |
| get_current_user(...) | Authorization ヘッダー | CurrentUser | 401・403・503 |
| require_role(*roles) | ロール | 依存関数 | ForbiddenError(403) |
| rate_limit(name, setting, window) | 名前・設定の項目名 | 依存関数 | RateLimitError(429) |
| service.logout(redis, user, now) | CurrentUser | なし | なし |

## ログアウト(6-5)

```
POST /auth/logout
  ttl = トークンの期限 - 今
  ttl > 0 なら SET revoked_session:<session_id> "1" EX ttl
```
期限を過ぎたトークンは、どのみち使えないので記録しない(Redis を太らせない)。

💡 なぜ Redis?:失効リストは毎リクエスト読むので速さが必要。期限で自動的に消える(EX)ので掃除もいらない。

## レート制限の依存関数

```
@router.post("/posts", dependencies=[Depends(rate_limit("posts", "rate_limit_posts_per_minute"))])
  キー:rl:posts:<user_id>:<分の番号>
  INCR → 初回だけ EXPIRE 61秒 → 上限を超えたら 429 + Retry-After
```
