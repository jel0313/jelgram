# 詳細設計:基盤(第0・5・8・15・17・22章)

対象:`app/main.py`・`app/core/`・`app/health/`

## 起動から終了まで(17-5)

```
uvicorn 起動
  ↓ create_app():ログ設定 → Sentry → FastAPI() → ミドルウェア → 例外ハンドラー → ルーター
  ↓ lifespan(前半):Redis・Storage・Gemini のクライアントを作り app.state に置く
リクエストを処理
  ↓ 終了の合図(SIGTERM)
  ↓ Uvicorn が処理中のリクエストを最大 20 秒待つ(--timeout-graceful-shutdown)
  ↓ lifespan(後半):クライアントを閉じる → DB の接続を全部閉じる
```

## 1 回のリクエストが通る順番

```
RequestContextMiddleware … request_id を付ける・アクセスログ・メトリクス・想定外エラーを 500 に
SecurityHeadersMiddleware … nosniff・DENY・no-referrer・CSP・HSTS(本番)・no-store
BodySizeLimitMiddleware …… 1MB(画像は 6MB)を超えたら 413
CORSMiddleware …………… CORS_ALLOW_ORIGINS のオリジンだけ
ルーター → 依存関数 → service → repository → DB
```

💡 なぜ素の ASGI で書く?:`@app.middleware("http")`(BaseHTTPMiddleware)は、SSE のストリーミングや contextvars と相性が悪い。

## 設定の切り替え(0-3)

| | development | test | production |
|---|---|---|---|
| /docs | 公開 | 公開 | 非公開 |
| HSTS | なし | なし | あり |
| CORS に localhost | 可 | 可 | 起動時にエラー |
| METRICS_TOKEN | 任意 | 任意 | 必須 |

## 入力チェック・例外

| 対象 | ルール | 違反時 |
|---|---|---|
| X-Request-ID | `^[A-Za-z0-9-]{1,64}$` | 使わずに新しく作る |
| 本文サイズ | Content-Length と実際の受信量の両方 | 413 |
| カーソル | base64 の JSON(t・i) | 400 |
