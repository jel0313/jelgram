# 詳細設計:投稿・いいね・タイムライン(第3・4・10章)

対象:`app/posts/`

## 処理フロー

### 投稿する(POST /posts)

```
① レート制限(10回/分)
② PostCreate の検証:本文 1〜500 字(前後の空白を除く)・画像 0〜10 枚・重複なし・余計な項目は 422
③ 禁止語 → 400 content_not_allowed
④ Idempotency-Key があれば begin()
     登録済み・同じ中身 → 保存済みの応答を返して終わり
     登録済み・違う中身 → 422 idempotency_key_reused
⑤ 画像:自分の・未使用・failed でない → そろわなければ 400 media_not_usable
⑥ insert posts → post_media(並び順)→ ハッシュタグ → Outbox(post.moderate)
⑦ 応答を作る → 冪等性キーに保存 → commit(全部まとめて確定)
```

### 編集する(PUT・PATCH /posts/{id})

```
所有者チェック:ない → 404 / 見えない他人の投稿 → 404 / 見える他人の投稿 → 403
PUT  :content・comments_disabled を全部置き換え(model_dump)
PATCH:送られた項目だけ(model_dump(exclude_unset=True))
update … where id = :id and version = :version returning version
  0 件 → 409 post_version_conflict(楽観的ロック)
本文が変わったら、ハッシュタグを付け直し・AI 判定をもう一度
```

### 削除する(DELETE /posts/{id})

```
1 トランザクションで:deleted_at = now → いいね削除・カウンタ 0 → コメント論理削除
                    → 通知削除 → 画像の行を削除(パスを返す)→ Outbox(media.delete)→ 監査ログ
失敗したら全部ロールバック。ストレージのファイルは確定後にワーカーが消す
人気投稿のキャッシュを消す
```

### いいね(POST・DELETE /posts/{id}/like)

```
見えない投稿 → 404
insert likes … on conflict do nothing returning
  入った → update posts set like_count = like_count + 1(アトミック)→ 通知
  入らない(いいね済み)→ 今の数を返す(エラーにしない = 冪等)
```

## SQL(repository.py)

```sql
-- 一覧・詳細で共通(:viewer_id = 閲覧者)
select p.*, a.username …,
       exists (select 1 from likes l where l.post_id = p.id and l.user_id = :viewer_id) as liked_by_me
from posts p
join profiles a on a.id = p.user_id
left join media am on am.id = a.avatar_media_id
where p.deleted_at is null and p.hidden_at is null   -- post_is_alive
  and <can_view_content_of(a)>                        -- 有効・ブロックなし・公開かフォロワー

-- カーソル(1ページ目は :cursor_t が null)
and (cast(:cursor_t as timestamptz) is null
     or (p.created_at, p.id) < (cast(:cursor_t as timestamptz), cast(:cursor_id as bigint)))
order by p.created_at desc, p.id desc
limit :limit + 1          -- 1件多く取り、次のページがあるかを知る

-- 画像をまとめて取る(N+1 対策)
select pm.post_id, m.* from post_media pm join media m on m.id = pm.media_id
where pm.post_id = any(:ids) order by pm.post_id, pm.position

-- 検索(値は必ずバインド変数。% _ \ はエスケープ)
… and p.content ilike :pattern escape '\'
```

### N+1 とは(4-6)

```
悪い例:投稿を20件取る(1回)→ 1件ずつ画像を取る(20回)= 21回
この実装:投稿(1回)+ 画像(1回)+ タグ(1回)+ 署名付き URL(1回)= 4回
```
ORM なら `selectinload(Post.media)` が同じことをする(where post_id in (...) を1回)。

### SQL インジェクション(8-5)

```python
# だめな例:検索語を SQL に直接埋め込む
text(f"select … where content ilike '%{q}%'")   # q = "' or 1=1 --" で全件・q 次第で削除も
# この実装:値はバインド変数で渡す。SQL の文と値が分かれて送られる
text("select … where content ilike :pattern"), {"pattern": f"%{escape_like(q)}%"}
```
並び順(列名)はバインド変数にできないので、`_ORDER_BY` の辞書にある SQL だけを使う。

## 入力チェック

| 項目 | ルール |
|---|---|
| content | 前後の空白を除いて 1〜500 字 |
| media_ids | 0〜10・重複なし・自分の未使用の画像 |
| version | 1 以上(PUT・PATCH で必須) |
| sort | new・likes のどちらか |
| limit | 1〜50 |
| Idempotency-Key | 255 字まで |
