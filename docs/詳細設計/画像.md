# 詳細設計:画像(第9章)

対象:`app/media/`・ワーカーの `handle_media_process`

## 処理フロー

### A. API 経由のアップロード(POST /media。9-1)

```
5MB + 1 バイトまでだけ読む
  ↓ validate_image:サイズ → マジックバイト → 申告の MIME と一致 → 拡張子と一致 → Pillow で開ける・画素数
  ↓ 保存名:<owner_id>/<uuid>.<拡張子>(クライアントのファイル名は使わない。9-4)
  ↓ Storage へ upload
  ↓ media に insert(status = pending)+ Outbox(media.process)→ commit
       DB が失敗 → Storage のファイルを消す(補償処理)
```

### B. 直接アップロード(9-7)

```
POST /media/upload-url → 署名付きアップロード URL と media_id
ブラウザ → Storage へ PUT(API を通らないので、API サーバーの帯域・メモリを使わない)
POST /media/{id}/complete → Storage から読んで A と同じ検証
     だめ → ファイル削除・status = failed / よし → Outbox(media.process)
```

### 加工(ワーカー。9-8)

```
download → exif_transpose(向きを反映)→ EXIF なしで保存し直す(GIF はそのまま)
→ 長辺 320px の WebP サムネイル → 両方 upload → status = ready・幅・高さ
```

### 取得(GET /media/{id}。9-6)

```
見てよい画像か(SQL)→ だめなら 404
署名付き URL(既定 10 分)を返す。バケットは非公開なので、URL がないと見られない
```
投稿の一覧では、画像・アイコンの URL を1回の通信でまとめて作る(signed_urls)。

## 検証の順番(9-3)

| 順 | チェック | だめなとき |
|---|---|---|
| 1 | サイズ 5MB 以下 | 413 image_too_large |
| 2 | マジックバイト(JPEG・PNG・GIF・WebP) | 415 unsupported_image |
| 3 | 申告された Content-Type と中身が一致 | 415 |
| 4 | 拡張子と中身が一致 | 415 |
| 5 | Pillow で開ける・最後まで読める | 400 broken_image |
| 6 | 縦×横 4000 万画素以下 | 413 |

💡 なぜマジックバイト?:拡張子と Content-Type はクライアントが自由に偽れる。ファイルの先頭の数バイトは中身そのもの。SVG はスクリプトを含められるので許可しない。

## SQL

```sql
-- 見てよい画像(自分の / 見てよい投稿の / ブロック関係にない人のアイコン / 見てよいストーリー)
select … from media m where m.id = :id and (
  m.owner_id = :viewer_id
  or exists (select 1 from post_media pm join posts p … where <post_is_alive> and <can_view_content_of(a)>)
  or exists (select 1 from profiles a where a.avatar_media_id = m.id and <not_blocked(a)>)
  or exists (select 1 from stories s … where s.expires_at > now() and <can_view_content_of(a)>)
)
```

## プロフィール画像の差し替え(9-9)

```
新しい画像を A の流れで登録 → profiles.avatar_media_id を付け替え
→ 古い画像の行を削除・Outbox(media.delete)→ commit → キャッシュ削除
```

| BrokenImageError | 400 |
