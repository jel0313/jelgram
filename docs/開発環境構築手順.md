# 開発環境構築手順

jelgram をローカルで開発できる状態にするまでの手順。
進捗は [WBS](WBS_進捗管理表.md) で管理する。手順が実際と違った場合は、このファイルを修正する。

## 1. 事前準備

### 1.1 アカウントの用意

1. **GitHub**:`jel0313` アカウント(作成済み・push 確認済み)
2. **Supabase**:GitHub アカウントでサインアップ
3. **Vercel**:GitHub アカウント(`jel0313`)でサインアップ(Hobby プラン)
4. **Render**:GitHub アカウント(`jel0313`)でサインアップ(無料プラン)
5. **Google Cloud / Google AI Studio**:個人の Google アカウントでログインできることを確認

**完了条件**:すべてのサービスにログインできる

### 1.2 ローカルツールの導入

使うツールは 1.3 で決めたもの(要件定義書 5.1)。

1. Xcode のライセンスに同意する(Homebrew でツールを入れる際に必要)。同意済みかは `xcodebuild -license check` で確認でき、何も表示されなければ同意済み
   ```
   sudo xcodebuild -license accept
   ```
2. Homebrew で uv・fnm・pnpm をインストールする
   ```
   brew install uv fnm pnpm
   ```
3. fnm で Node.js の LTS 版をインストールする
   ```
   fnm install --lts
   ```
4. `~/.zshrc` の末尾に fnm の設定を追加し、ターミナルを開き直す
   ```
   # --- fnm (Node.js のバージョン管理。.node-version があるディレクトリで自動切替) ---
   eval "$(fnm env --use-on-cd --version-file-strategy=recursive --shell zsh)"
   ```
   - conda・pyenv の設定より後ろ(ファイルの末尾)に書く。先に書くと、Homebrew で入れた別の Node が優先されることがある
5. Python 本体の個別インストールは不要。uv が `.python-version` を見て、必要なら Python をダウンロードし、プロジェクトごとの仮想環境(`apps/api/.venv`)も自動で作成する
   - `uv sync` / `uv run` を実行すると `.venv` が作られ、そこが使われる。`source .venv/bin/activate` による有効化も不要
   - conda・pyenv はこのプロジェクトでは使わない(削除する必要はない)
6. エディタに拡張機能を入れる(Python、ESLint、Tailwind CSS IntelliSense)

**完了条件**:新しいターミナルで以下のバージョンが表示される

```
node -v        # v24.x
pnpm -v
uv --version
```

## 2. リポジトリ初期化

### 2.1 ディレクトリ構成の作成

1. 要件定義書 7.1 の構成でディレクトリを作る(`apps/web`、`apps/api`、`supabase/migrations`)
   - 空のディレクトリは Git で管理されないため、`supabase/migrations/.gitkeep` を置く
2. ルートに `.gitignore` を作成する
   - `.env` と `.env.*` を除外し、`!.env.example` でひな形だけはコミット対象に戻す
   - `node_modules/`、`.next/`、`.venv/`、`__pycache__/` など、自動生成されるものを除外
   - `git check-ignore -v apps/web/.env.example` で、`!.env.example` のルールが表示されれば、ひな形はコミット対象になっている

### 2.2 バージョン固定

| ファイル                  | 内容   | 読み取るツール                                           |
| ------------------------- | ------ | -------------------------------------------------------- |
| `.node-version`(ルート) | `24`   | fnm(`apps/web` など下の階層でも有効)                  |
| `apps/api/.python-version` | `3.13` | uv(Render もこのファイルを参照する)                   |

確認方法:新しいターミナルで以下を実行する

```
cd apps/web && node -v          # v24.x
cd ../api && uv python find     # 3.13 系の Python のパス
```

### 2.3 環境変数のひな形

`apps/web/.env.example` と `apps/api/.env.example` を作成する。秘密の値は空にし、秘密でない初期値(レート制限の上限値など)は記入しておく。

- web:Supabase の URL・公開キー(publishable key)、API の URL
- api:Supabase の URL・秘密鍵(secret key)・DB 接続文字列・Storage バケット名、Gemini APIキー・モデル名、レート制限の上限値、CORS 許可オリジン

実際に使うときは、ひな形をコピーして値を入れる(3. 開発用 Supabase 構築で行う)

```
cp apps/web/.env.example apps/web/.env.local
cp apps/api/.env.example apps/api/.env
```

> **注意**:フロントエンドのひな形作成(`create-next-app`)は、空でないディレクトリだとエラーになる。その時点で `apps/web/.env.example` と `apps/web/.env.local` を一時的に別の場所へ移し、作成後に戻す。

**完了条件**:ディレクトリ構成と設定ファイルが GitHub に push されている

## 3. 開発用 Supabase 構築

### 3.1 プロジェクト作成

1. [Supabase のダッシュボード](https://supabase.com/dashboard) で **New project** を押し、以下で作成する
   - Project name:`jelgram-dev`
   - Database Password:**Generate a password** で自動生成し、**その場でパスワードマネージャーに保存する**(後から画面で確認することはできない)。記号(`?` `+` `@` `/` 等)が含まれる場合は接続文字列で問題になるため、英数字のみになるまで生成し直す
   - Region:Northeast Asia (Tokyo)
2. 接続情報を控える
   - Project URL:Project Settings → Data API
   - Publishable key(`sb_publishable_...`)・Secret key(`sb_secret_...`):Project Settings → API Keys
   - DB 接続文字列:画面上部の **Connect** ボタン → **Session pooler** のもの(Direct connection は IPv6 専用で、家庭の回線や Render 無料プランからつながらないことがある)
3. ひな形をコピーして値を設定する
   ```
   cp apps/web/.env.example apps/web/.env.local
   cp apps/api/.env.example apps/api/.env
   ```
   - `apps/web/.env.local`:`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `apps/api/.env`:`SUPABASE_URL`、`SUPABASE_SECRET_KEY`、`DATABASE_URL`(接続文字列の `[YOUR-PASSWORD]` を `[ ]` ごと DB パスワードに置き換える)

> **注意**:Secret key・DB パスワードは、チャットやメモ用ファイル等に貼らない。Publishable key はブラウザに公開される前提のキーのため問題ない。DB パスワードを失くした場合は、Project Settings → Database → **Reset database password** で再発行する。

> VS Code で「ターミナル環境への取り込みは無効になっています(`python.terminal.useEnvFile`)」という通知が出るが、有効にしなくてよい(FastAPI が起動時に `.env` を自分で読み込むため)。

**完了条件**:`apps/api/.env` の `DATABASE_URL` で DB に接続できる

### 3.2 テーブル作成

1. テーブル作成の SQL は [supabase/migrations/20260928000000_initial_schema.sql](../supabase/migrations/20260928000000_initial_schema.sql) に作成済み
   - `profiles`、`posts`、`likes`、`chat_messages` とインデックス
   - 新規ユーザー登録時に `profiles` を自動作成するトリガー(Google の名前・アイコンを初期値にする)
   - 全テーブルで RLS を有効化(ポリシーは作らず、ブラウザからのテーブル直接アクセスを禁止。DB へのアクセスは FastAPI 経由のみのため)
2. Supabase の **SQL Editor** → **New query** に SQL ファイルの中身をすべて貼り付け、**Run** を押す
3. 「Success. No rows returned」と表示されれば成功

**完了条件**:Table Editor で4テーブルが確認できる

> 以降のスキーマ変更も、`supabase/migrations/` に日時付きの SQL ファイルを追加し、同じ手順で開発用 → 本番用の順に実行する。

### 3.3 Storage 作成

1. バケット作成の SQL は [supabase/migrations/20260928010000_storage_post_images.sql](../supabase/migrations/20260928010000_storage_post_images.sql) に作成済み
   - バケット名 `post-images`、公開バケット
   - 上限 5MB、形式は JPEG / PNG / WebP / GIF(要件定義書 3.4)
2. 3.2 と同じく SQL Editor で実行する
3. Storage の画面に `post-images` が表示されることを確認する

**完了条件**:以下を満たす(管理画面からテスト画像をアップロードして確認できる)

- 画像をアップロードでき、公開URLで表示できる
- 5MB を超えるファイル、画像以外のファイルはアップロードできない
- テスト用にアップロードした画像は、確認後に削除する

### 3.4 Google ログインの設定

> **注意**:管理画面は [https://console.cloud.google.com/](https://console.cloud.google.com/)。`cloud.google.com/free` などの宣伝ページではない。「無料で開始」「無料トライアル」(クレジットカード登録)は不要で、申し込まない。請求先アカウントの設定を求められてもスキップする。

1. **プロジェクト作成**
   - 画面左上のプロジェクト選択 → **新しいプロジェクト** → 名前 `jelgram-dev` で作成
   - 作成後、プロジェクト選択で `jelgram-dev` を選んだ状態にする
2. **OAuth 同意画面**(☰ → API とサービス → OAuth 同意画面 → Google Auth Platform)
   - **開始** → アプリ名 `jelgram (dev)`、サポートメール・連絡先に自分の Gmail、対象は **外部** → 作成
   - **対象(Audience)** → **テストユーザー** に、ログインに使う自分の Gmail を追加(テスト中はここに追加した人しかログインできない)
3. **OAuth クライアント ID**(Google Auth Platform → クライアント → クライアントを作成)
   - 種類:**ウェブ アプリケーション**、名前:`jelgram-dev-web`
   - 承認済みの JavaScript 生成元:`http://localhost:3000`
   - 承認済みのリダイレクト URI:`https://<Supabase のプロジェクトID>.supabase.co/auth/v1/callback`
   - 作成後に表示される **クライアント シークレットはこの画面でしか見られない**ため、すぐにパスワードマネージャーに保存する
4. **Supabase に登録**(Authentication → Sign In / Providers → Google)
   - **Enable Sign in with Google** をオンにし、Client IDs・Client Secret を入力して Save
   - 画面の Callback URL が 3 のリダイレクト URI と一致していることを確認する
5. **リダイレクト先の登録**(Authentication → URL Configuration)
   - Site URL:`http://localhost:3000`
   - Redirect URLs:`http://localhost:3000/**`

> **注意**:クライアント シークレットをリポジトリ内のファイル(`docs/` 配下など)に書かない。個人メモ用の `docs/設定/` は `.gitignore` で除外しているが、秘密情報はパスワードマネージャーに保管するのが原則。

**完了条件**:Google プロバイダーが有効になっている(実際のログイン確認は、フロントエンドの認証機能を作るときに行う)

確認方法(Publishable key で公開設定を取得し、`"google":true` が含まれていればよい)

```
curl -s "https://<プロジェクトID>.supabase.co/auth/v1/settings" -H "apikey: <Publishable key>"
```

### 3.5 Gemini APIキーの発行(開発用)

1. Google AI Studio で、3.4 の開発用 Google Cloud プロジェクトに紐づけて APIキーを発行する
2. [レート制限画面](https://aistudio.google.com/rate-limit) で Flash-Lite 系の無料枠の実際の値を確認し、要件定義書 4.2・4.3 の数値と合っているか確かめる
3. APIキーをローカルの `apps/api/.env` に設定する

**完了条件**:APIキーを発行し、無料枠の値を確認済み
