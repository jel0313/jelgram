# 開発環境構築手順

jelgram をローカルで開発できる状態にするまでの手順。
進捗は [WBS](WBS_進捗管理表.md) で管理する。手順が実際と違った場合は、このファイルを修正する。

## 1. 事前準備

### 1.1 アカウントの用意

1. **GitHub**:`jel0313` アカウント(作成済み・push 確認済み)
2. **Supabase**:GitHub アカウントでサインアップ
3. **Vercel**:GitHub アカウント(`jel0313`)でサインアップ(Hobby プラン)
4. **Render**:GitHub アカウント(`jel0313`)でサインアップ(無料プラン)
5. **Google Cloud / Google AI Studio**:個人の Google アカウントでログインできることを確認

**完了条件**:すべてのサービスにログインできる

### 1.2 ローカルツールの導入

使うツールは 1.3 で決めたもの(要件定義書 5.1)。

1. Xcode のライセンスに同意する(Homebrew でツールを入れる際に必要)。同意済みかは `xcodebuild -license check` で確認でき、何も表示されなければ同意済み
   ```
   sudo xcodebuild -license accept
   ```
2. Homebrew で uv・fnm・pnpm をインストールする
   ```
   brew install uv fnm pnpm
   ```
3. fnm で Node.js の LTS 版をインストールする
   ```
   fnm install --lts
   ```
4. `~/.zshrc` の末尾に fnm の設定を追加し、ターミナルを開き直す
   ```
   # --- fnm (Node.js のバージョン管理。.node-version があるディレクトリで自動切替) ---
   eval "$(fnm env --use-on-cd --version-file-strategy=recursive --shell zsh)"
   ```
   - conda・pyenv の設定より後ろ(ファイルの末尾)に書く。先に書くと、Homebrew で入れた別の Node が優先されることがある
5. Python 本体の個別インストールは不要。uv が `.python-version` を見て、必要なら Python をダウンロードし、プロジェクトごとの仮想環境(`apps/api/.venv`)も自動で作成する
   - `uv sync` / `uv run` を実行すると `.venv` が作られ、そこが使われる。`source .venv/bin/activate` による有効化も不要
   - conda・pyenv はこのプロジェクトでは使わない(削除する必要はない)
6. エディタに拡張機能を入れる(Python、ESLint、Tailwind CSS IntelliSense)

**完了条件**:新しいターミナルで以下のバージョンが表示される

```
node -v        # v24.x
pnpm -v
uv --version
```

## 2. リポジトリ初期化

### 2.1 ディレクトリ構成の作成

1. 要件定義書 7.1 の構成でディレクトリを作る(`apps/web`、`apps/api`、`supabase/migrations`)
   - 空のディレクトリは Git で管理されないため、`supabase/migrations/.gitkeep` を置く
2. ルートに `.gitignore` を作成する
   - `.env` と `.env.*` を除外し、`!.env.example` でひな形だけはコミット対象に戻す
   - `node_modules/`、`.next/`、`.venv/`、`__pycache__/` など、自動生成されるものを除外
   - `git check-ignore -v apps/web/.env.example` で、`!.env.example` のルールが表示されれば、ひな形はコミット対象になっている

### 2.2 バージョン固定

| ファイル                  | 内容   | 読み取るツール                                           |
| ------------------------- | ------ | -------------------------------------------------------- |
| `.node-version`(ルート) | `24`   | fnm(`apps/web` など下の階層でも有効)                  |
| `apps/api/.python-version` | `3.13` | uv(Render もこのファイルを参照する)                   |

確認方法:新しいターミナルで以下を実行する

```
cd apps/web && node -v          # v24.x
cd ../api && uv python find     # 3.13 系の Python のパス
```

### 2.3 環境変数のひな形

`apps/web/.env.example` と `apps/api/.env.example` を作成する。秘密の値は空にし、秘密でない初期値(レート制限の上限値など)は記入しておく。

- web:Supabase の URL・公開キー(publishable key)、API の URL
- api:Supabase の URL・秘密鍵(secret key)・DB 接続文字列・Storage バケット名、Gemini APIキー・モデル名、レート制限の上限値、CORS 許可オリジン

実際に使うときは、ひな形をコピーして値を入れる(3. 開発用 Supabase 構築で行う)

```
cp apps/web/.env.example apps/web/.env.local
cp apps/api/.env.example apps/api/.env
```

> **注意**:フロントエンドのひな形作成(`create-next-app`)は、空でないディレクトリだとエラーになる。その時点で `apps/web/.env.example` と `apps/web/.env.local` を一時的に別の場所へ移し、作成後に戻す。

**完了条件**:ディレクトリ構成と設定ファイルが GitHub に push されている

## 3. 開発用 Supabase 構築

### 3.1 プロジェクト作成

1. Supabase で開発用プロジェクトを作成する(名前例:`jelgram-dev`、リージョン:Tokyo)
2. データベースのパスワードをパスワードマネージャー等に保管する
3. Project Settings から URL・APIキー・DB 接続文字列を控え、ローカルの `.env` に設定する

### 3.2 テーブル作成

1. 要件定義書 8章のテーブルを作成する SQL を `supabase/migrations/` に書く
   - `profiles`、`posts`、`likes`、`chat_messages`
   - `likes` の複合主キー `(user_id, post_id)`
   - `chat_messages` の `(user_id, created_at)` インデックス
2. 新規ユーザー登録時に `profiles` を自動作成するトリガーを作る(Google の名前・アイコンを初期値にする)
3. 全テーブルで RLS(行レベルセキュリティ)を有効にし、ブラウザからのテーブル直接アクセスを禁止する(DB へのアクセスは FastAPI 経由のみのため)
4. SQL を Supabase の SQL Editor で実行する

**完了条件**:Table Editor で4テーブルが確認できる

### 3.3 Storage 作成

1. 画像用のバケットを作成する(名前例:`post-images`、公開バケット)
2. ファイルサイズ上限と許可する形式(JPEG / PNG / WebP 等)をバケット設定で指定する

**完了条件**:管理画面からテスト画像をアップロードし、公開URLで表示できる

### 3.4 Google ログインの設定

1. Google Cloud で開発用プロジェクトを作成する(名前例:`jelgram-dev`)
2. OAuth 同意画面を設定する(外部、テストユーザーに自分のアカウントを追加)
3. OAuth クライアント ID(ウェブアプリケーション)を作成し、承認済みのリダイレクト URI に Supabase のコールバック URL を登録する
4. Supabase の Authentication → Providers → Google に、クライアント ID とシークレットを設定する
5. Supabase の Authentication → URL Configuration に `http://localhost:3000` を登録する

**完了条件**:設定画面上で Google プロバイダーが有効になっている(実際のログイン確認は、フロントエンドの認証機能を作るときに行う)

### 3.5 Gemini APIキーの発行(開発用)

1. Google AI Studio で、3.4 の開発用 Google Cloud プロジェクトに紐づけて APIキーを発行する
2. [レート制限画面](https://aistudio.google.com/rate-limit) で Flash-Lite 系の無料枠の実際の値を確認し、要件定義書 4.2・4.3 の数値と合っているか確かめる
3. APIキーをローカルの `apps/api/.env` に設定する

**完了条件**:APIキーを発行し、無料枠の値を確認済み
