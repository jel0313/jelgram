# WBS:jelgram

開発の進捗を管理する資料。各作業の具体的な内容は「資料」列のファイルを参照する。

## 使い方

- 状態の記号:⬜ 未着手 / 🔄 作業中 / ✅ 完了 / ⏸ 保留 / ➖ 対象外
- 作業を始めたら 🔄、終わったら ✅ にする。すべての工程が ✅ になったら完了日を記入する
- 1次開発は **モック先行** で進める([要件定義書](要件定義書.md) 7.4)
  - 工程 4:先に全画面のモック(Next.js + shadcn/ui・ダミーデータ)を作る
  - 工程 5:機能ごとに「API 仕様 → API → テスト → 画面接続 → 打鍵」の順に進める。API 仕様は `docs/API仕様/<ID>_<機能名>.md` に置き、「資料」列にリンクする
  - 4.1・4.2 は旧方式(詳細設計書・マニュアル)で実装済み。資料は `docs/詳細設計_手順/` に残している
- 2次開発以降は、要件定義書 12章のロードマップに沿って、着手時に同じ形式で追記する

#### 作業ごとの作るもの

画面は [画面設計](画面設計/画面一覧.md) の番号。「置き換える」は、画面接続でダミーから本物の API 呼び出しに変える関数。

**認証**

- **5.1 ログイン・ログアウト**:画面 01・09 / API なし(Supabase Auth を画面から使う)/ 置き換える:`lib/auth.ts` の `signInWithGoogle`・`signOut`・`getSessionUser`
  - 完了の目安:Google でログインするとタイムラインへ、ログアウトするとログイン画面へ。再読み込みしてもログインが続く
- **5.2 API にトークンを付ける**:画面なし / API は 4.2 で作成済み(`GET /me`)/ 作るもの:API を呼ぶ共通の関数(`Authorization: Bearer <トークン>` を付ける・エラーを `ApiError` にする)
  - 完了の目安:画面から `GET /me` を呼ぶと自分の id が返る。ログアウト中は 401

**共通**

- **5.3 DB 接続の準備**:API から DB に接続する仕組み(SQLAlchemy + psycopg。SQL は生で書く。要件定義書 5.1・[バックエンド構成](バックエンド構成.md) 8章)
  - 完了の目安:API の中から `profiles` を読める。テストで DB を使い、終わったらデータが残らない
- **5.5 API の型定義出力**:FastAPI の `/openapi.json` から TypeScript の型を生成する仕組み(要件定義書 7.1)/ 置き換える:`lib/api/types.ts`
  - 完了の目安:API の形を変えて生成し直すと、画面側の型の違いがエラーで分かる

**タイムライン**

- **5.4 投稿一覧の表示**:画面 02 / API `GET /posts` / 置き換える:`getTimeline`
  - 完了の目安:新しい順に表示される。投稿者の名前・アイコン、いいね数、自分がいいね済みか(ハートの色)が正しい
  - 進み具合:DB に確認用の投稿を入れて SQL を確認 ✅ → `schemas.py` ✅ → `repository.py` ✅ → `service.py` ⬜ → `router.py`・`main.py` ⬜ → テスト ⬜ → 画面接続 ⬜ → 打鍵 ⬜
- **5.6 投稿詳細の表示**:画面 03 / API `GET /posts/{id}` / 置き換える:`getPost`
  - 完了の目安:URL で投稿を開ける。ない投稿は「投稿が見つかりません」
- **5.7 投稿する(文字だけ)**:画面 02 / API `POST /posts` / 置き換える:`createPost`
  - 完了の目安:投稿が一覧の先頭に出て、再読み込みしても残る。空・501 文字以上は弾かれる
- **5.8 いいねする・取り消す**:画面 02・03 / API `POST /posts/{id}/like`・`DELETE /posts/{id}/like` / 置き換える:`likePost`・`unlikePost`
  - 完了の目安:押すたびにいいね・取り消しが切り替わる。2 回続けて押しても数がずれない。他の人のいいねも数に入る
- **5.9 画像付きで投稿する**:画面 02・05 / API `POST /uploads/presign`(署名付き URL の発行)と、`POST /posts` の `image_url` のチェック(自分のバケットの URL だけ。要件定義書 3.4)/ 置き換える:`uploadImage`
  - 完了の目安:画像付きの投稿が再読み込みしても表示される。5MB を超える・形式が違う画像は弾かれる

**AI チャット**

- **5.10 メッセージを送って応答を受け取る**:画面 04 / API `POST /chat` / 置き換える:`sendChatMessage`
  - 中身:Gemini を呼ぶ。キャラクターはシステムプロンプトで決める(要件定義書 3.3・3.5)。会話は `chat_messages` に保存する
  - 完了の目安:辛口ツッコミ系の口調で応答が返る
- **5.11 会話の履歴の表示・新しい会話**:画面 04 / API `GET /chat/history` / 置き換える:`getChatHistory`
  - 完了の目安:再読み込みしても会話が残る。「新しい会話」で空から始まり、前の会話とは混ざらない
- **5.12 「この投稿について」で質問する**:画面 04 / API `POST /chat` の `post_id` / 置き換える:なし(5.10 の関数がそのまま使える)
  - 完了の目安:投稿の内容を踏まえた応答が返る。ない投稿を指定すると 404
- **5.13 レート制限**:画面 04 / API `POST /chat` に回数の制限(ユーザーごと・アプリ全体。回数は要件定義書 4.2)。超えたら 429 と、キャラクターの口調のメッセージ / 置き換える:429 を `RateLimitError` にする
  - 完了の目安:回数を超えると、チャットに黄色の枠でメッセージが出る。時間がたつとまた話せる
