# jelgram フロントエンド(apps/web)

Next.js + Tailwind CSS + shadcn/ui。今は **モック**(すべてダミーデータで動く)。

画面ごとの画像と仕様は [docs/画面設計](../../docs/画面設計/画面一覧.md)。「2次」「4次」などの印が付いた機能は、そのフェーズで API につなぐ。

## 起動

```
cd ~/dev/jelgram/apps/web
pnpm install
pnpm dev
```

http://localhost:3000 を開き、「Google でログイン」でログインする(Supabase Auth。`.env.local` に Supabase の URL・キーが必要)。

テストは `pnpm test`(Vitest)。

## ダミーデータの場所

画面がデータを取得・送信する処理は、すべて `lib/` の次のファイルに集めている。画面接続(WBS 5.x)では、ここの中身を本物の API 呼び出しに置き換える。

| ファイル             | 中身                                   |
| -------------------- | -------------------------------------- |
| `lib/auth.ts`        | ログイン・ログアウト(**Supabase Auth に接続済み**。5.1) |
| `lib/api/client.ts`  | API を呼ぶ共通の関数(トークンを付ける。**作成済み**。5.2) |
| `lib/api/posts.ts`   | タイムライン・投稿・いいね             |
| `lib/api/uploads.ts` | 画像アップロード                       |
| `lib/api/chat.ts`    | AI チャット(送信・履歴・会話の一覧)  |
| `lib/api/users.ts`   | ユーザーページ・プロフィール編集(4次) |
| `lib/api/types.ts`   | API の入出力の形                       |
| `lib/api/mock-data.ts` | ダミーデータ(全部つないだら削除)    |

## モックで確認できる表示

| 確認したいもの             | 操作                                   |
| -------------------------- | -------------------------------------- |
| タイムラインの読み込み失敗 | URL に `?mock_error=1` を付けて開く    |
| AI チャットのレート制限    | チャットで `/429` と送る               |
| スマホの表示               | ブラウザの幅を狭くする(1024px 未満でチャットが右下のボタンになる) |

- ダミーデータはブラウザのメモリにあるだけなので、ページを再読み込みすると、投稿・いいね・チャットは最初の状態に戻る
